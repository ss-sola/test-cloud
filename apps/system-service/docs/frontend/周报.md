# 周报生成模块

## 功能

管理台的“周报生成”菜单通过 GitHub Commits API 获取项目提交，生成上周或本周的 Markdown 汇总。

| 管理台周期 | 时间范围 | 行为 |
| --- | --- | --- |
| `last-week` | 上一完整周，周一至周日 | 按工作日合并展示 |
| `this-week` | 本周一至当前时刻 | 按项目展示并生成去重摘要 |

服务端先按 `author`、分支和时间窗口请求 GitHub 提交，再过滤 `Merge pull request`、`Merge branch` 和多 parent 合并提交。生成摘要前统一清理提交类型前缀，剔除空标题、纯代码集成和标题与完整正文都相同的重复记录；正文不同的同标题提交分别保留。语言过滤仅要求标题或正文包含中文，中英混写保留，完全不含中文才过滤。过滤后的数据同时用于统计、日期分组和模型摘要；不提供本地规则摘要降级。

## 接口

`POST /api/weekly-commit-reports/generate`

同步生成请求必须显式携带完整的 `runtime`，不从服务端配置补值：

```json
{
  "period": "last-week",
  "configs": [
    {
      "repo": "https://github.com/example/project.git",
      "person": "person@example.com",
      "branch": "merge/wzj-temp"
    }
  ],
  "runtime": {
    "githubToken": "<github-token>",
    "ai": {
      "baseUrl": "https://api.example.com/v1",
      "apiKey": "<api-key>",
      "model": "gpt-4o-mini",
      "enableThinking": false
    }
  }
}
```

异步生成任务可选开启飞书发布：

```json
{
  "period": "last-week",
  "configs": [
    {
      "repo": "https://github.com/example/project.git",
      "person": "person@example.com",
      "branch": "merge/wzj-temp"
    }
  ],
  "runtime": {
    "githubToken": "<github-token>",
    "ai": {
      "baseUrl": "https://api.example.com/v1",
      "apiKey": "<api-key>",
      "model": "gpt-4o-mini",
      "enableThinking": false
    }
  },
  "publish": {
    "enabled": true,
    "person": "张三",
    "settings": {
      "appId": "cli_xxxxxxxxx",
      "appSecret": "<app-secret>",
      "wikiUrl": "https://tthdtech.feishu.cn/wiki/SAxnwUjvZiiGbCk1uvNcZoFCnad?sheet=a0ab9d",
      "name": "张三"
    }
  }
}
```

`publish.settings` 是本次请求的飞书配置，启用时必须携带 App ID、App Secret 和单个 Wiki 地址，可选姓名、超时和重试参数；不读取 CLI 环境变量或旧服务端配置。Wiki 地址必须包含 `?sheet=` 查询参数，服务端固定只读 `A1:B200`，不接收月份、Sheet ID 或自定义查找范围。`publish.person` 优先于 `settings.name`；两者都未传时，仅在报告结果能推断出唯一人员时允许发布。同步 `POST /generate` 同样使用请求 runtime，不从服务端配置补值。


```text
GET https://api.github.com/repos/{owner}/{repo}/commits
  ?sha={branch}
  &author={person}
  &since={window.start.toISOString()}
  &until={window.end.toISOString()}
  &per_page=100
  &page=1...
```

`person` 应填写 GitHub login 或提交邮箱。`branch` 为空时不发送 `sha` 参数。每页最多 100 条，分页、提交、prompt 和输出上限由本次请求 `runtime.limits` 提供或使用代码常量。

响应仍位于统一响应包装的 `data` 字段：

```json
{
  "period": "last-week",
  "weekStart": "2026-08-17",
  "weekEnd": "2026-08-23",
  "markdown": "# person@example.com 上周任务日志\n...",
  "projects": [],
  "projectErrors": [],
  "commitCount": 12,
  "degraded": false,
  "dailySections": []
}
```

页面实际使用异步 Job 接口显示后端进度：

```http
POST /api/weekly-commit-reports/jobs
```

创建后返回 `jobId` 和初始 `progress`。页面随后轮询：

```http
GET /api/weekly-commit-reports/jobs/status?jobId=...
```

进度字段由服务端生成，包括 `phase`、`percent`、`completedProjects`、`totalProjects`、`failedProjects`、`currentProject` 和 `message`。阶段顺序为 `queued`、`validating`、`collecting`、`summarizing`、`finalizing`、`publishing`、`completed`；前端不再使用本地定时器伪造进度。页面提供“同步到飞书文档”复选框，默认不勾选；选择“本周”时该选项置灰，并以 `publish.enabled: false` 提交，避免服务端默认发布配置造成意外写入。选择“上周”并勾选后才会提交 `publish.enabled: true`。任务由固定的 BullMQ 队列 `weekly-report` 使用 `bull` prefix 执行，Worker 并发数为 2，完成或失败任务保留 30 分钟；`publication.status` 单独表示飞书发布的 `skipped`、`succeeded` 或 `failed`，发布失败不会丢失 `markdown`。原 `POST /generate` 同步接口继续保留兼容。

异步任务状态中的飞书字段示例：

```json
{
  "publication": {
    "status": "succeeded",
    "range": "sheet_id!C12:G12",
    "row": 12
  }
}
```

项目配置、飞书同步开关和飞书同步配置保存到 localStorage：

```text
nestcloud:weekly-report:v1
```

草稿中的 `publishSettings` 为单对象，包含 `appId`、`appSecret`、`wikiUrl` 和可选 `name`；`publishEnabled` 缺失或不是 `true` 时按未勾选处理，不迁移旧版 `monthlyTargets`。

Token 配置页为兼容继续使用 `nestcloud:release-tokens:v1`，只提供 GitHub Token、飞书 App ID/Secret 和可选的嵌套 AI 配置。历史数据中的 Jenkins 字段不在页面展示，下次显式保存不再写入：

```json
{
  "ai": {
    "baseUrl": "https://api.example.com/v1",
    "apiKey": "<api-key>",
    "model": "gpt-4o-mini",
    "enableThinking": false
  }
}
```

`baseUrl` 是 OpenAI-compatible 服务的基础地址，不包含 `/chat/completions`；周报服务端还要求它是无凭据、无 query/hash 的 HTTP(S) URL。三项去除首尾空白后必须全部填写，周报页面始终把完整配置作为本次请求的 `runtime.ai` 提交。`enableThinking` 是可选、非 nullable 的严格布尔开关，缺省为 `false`；Token 配置页“启用 AI 思考”默认未勾选，localStorage 旧值缺失或不为严格 `true` 均视为 `false`，周报同步 `/generate` 与异步 `/jobs` 请求均显式传入当前布尔值。模型客户端每次调用上游都发送 `enable_thinking: input.enableThinking ?? false`；不支持该参数的提供方可能报错，不自动删参数重试。Token 页仍可保存全部留空或部分填写的草稿，但会提示无法生成周报；周报页面在创建 Job 前拦截这些配置，后端也拒绝缺失或空白字段。AI API Key 与其他页面凭据一样明文保存在当前浏览器 localStorage，只应在受控 HTTPS 管理台中使用，并在离开环境前清空、定期轮换。

⚠️ 按当前产品要求，App Secret 会保存到浏览器 localStorage。任何能读取该浏览器存储的脚本、扩展或本机用户都可能获取它，因此只应在受信任的内部管理台和 HTTPS 环境使用，并应定期轮换飞书应用密钥。App Secret 不会写入 BullMQ Job data、Markdown、Job 状态、页面错误消息或服务日志；Worker 仅在当前进程的执行期使用它。

JSON/ENV 两侧输入分别保存到：

```text
nestcloud:compare:json:v1
nestcloud:compare:env:v1
```

存储损坏或不可用时回退到页面默认值，不影响当前页面操作；GitHub Token 和飞书 `tenant_access_token` 不会写入周报 Markdown、Job 状态或服务日志。AI API Key 由 Token 配置页从当前浏览器读取，仅随完整的本次周报请求发送，队列终态和状态接口不会返回它。

## 配置

每次请求都必须携带 `configs` 和 `runtime`，业务配置不从配置文件、环境变量或旧键回退。`runtime` 必须包含 `githubToken` 和完整 `ai`（`baseUrl`、`apiKey`、`model`），可选包含 `allowedRepositories` 及 `limits`（项目、提交、prompt、输出和超时上限）。AI 对象缺失、缺任意字段或字段去除首尾空白后为空时拒绝生成，即使预期无提交也不例外。这些字段由 Controller 的 DTO/class-validator 与服务入口校验，队列终态和状态接口不会返回 Token 或 AI key。

飞书发布配置由页面表单填写，并随异步 Job 的 `publish.settings` 参数传递。页面字段包括：

- `appId`、`appSecret`：飞书自建应用凭据，启用发布时必填。
- `wikiUrl`：单个 Wiki 或 Sheet 地址，必须通过 URL 的 `?sheet=` 参数指定 Sheet。
- `name`：可选的表格 B 列姓名；也可使用 `publish.person` 覆盖，均未传时从单一项目人员推断。
- `requestTimeoutMs`、`maxRetries`：可选的本次请求参数。
- 查找范围固定为 `A1:B200`，不作为页面或请求字段传递。

不再读取 `WeeklyReport*`、`FEISHU_CLI_*` 或旧 `monthlyTargets` 配置，也不执行历史迁移。

页面默认保存这些值到 `nestcloud:weekly-report:v1`，启用发布时连同本次请求的 App ID/App Secret 一起提交。

示例（请将 Sheet ID 放在 URL 的 `sheet` 查询参数中）：

```json
{
  "wikiUrl": "https://tthdtech.feishu.cn/sheets/ZVPMsdbHphQOdetitZbcMu7NnEd?sheet=a0ab9d",
  "name": "张三"
}
```

发布使用 `last-week` 的五个工作日摘要：固定只读 `A1:B200`，按 `8.24-8.28` 这类日期范围和姓名精确匹配唯一行；如果日期列使用纵向合并单元格，后续返回的 `null` 行会沿用最近一个非空日期范围。找到目标行后再读取该行 `C:G`，同一单元格内的多条摘要按 `1. `、`2. ` ` 等序号逐行写入。内容相同返回 `publication.status=skipped`；内容变化时只更新 `C{row}:G{row}`，不会清空或改动其它单元格。零行、多行、非 Sheet、权限不足或目标配置缺失均不会发起写入。`this-week` 暂不自动发布。

GitHub Token 和 AI 配置从 Token 配置页面的当前浏览器存储读取，并分别作为本次请求的 `runtime.githubToken` 与完整 `runtime.ai` 提交；不再从 `.env`、配置中心或 `GITHUB_TAG_FILE_TOKEN` 读取。页面不会展示 tenant token，服务端状态也不会返回 GitHub/AI/飞书凭据。

## 错误与运行边界

- GitHub URL、仓库白名单、字段格式和全局 Token 校验失败时，整份请求仍返回错误。
- 单个项目的 GitHub API 401、403、404、422、429、网络错误或超时会写入 `projectErrors`，跳过该项目并继续读取后续项目。
- `projects`、`commitCount` 和报告的项目数量只包含成功读取的项目，提交数按生成前统一过滤后的记录统计。
- `projectErrors` 始终是数组，每项包含 `repo`、`repoLabel`、`code` 和 `message`；异常也会追加到 Markdown 的“项目异常”区块。
- AI 配置缺失或空白返回 400；模型通过与工作流共用的 LangChain `AiTextClientService` 调用，旧周报仍显式传入超时、`temperature: 0.2` 与 50000 的响应字节/文本字符预算。AI 请求失败、空/非法响应、`finish_reason` 非 `stop`（含 `length` 截断）、无效摘要或 prompt 超限使整次生成失败，不使用本地规则替代；受控错误不回显上游正文或密钥。同步接口返回异常；异步任务进入 `failed`，不返回成功 Markdown，也不调用飞书发布。页面清空旧输出、隐藏复制/下载并清除旧项目异常。
- 无可用提交时不发起 AI 请求，但仍须先提供完整 AI 配置。页面标为“无可用提交（未调用 AI）”，不能据此证明 AI 可用。
- 公开 `degraded` 仅为历史结果兼容保留，新成功结果固定为 `false`。页面优先将历史 `degraded=true` 标为“历史本地结果”；否则仅有可用提交的结果标为“AI 摘要”，不把项目采集失败等同于降级。
- 生产环境应通过受控管理网络或反向代理保护接口，并配置 GitHub API 速率限制。

## 摘要表达与完整性

日报和项目周报统一要求中文业务描述，每条写清业务对象及具体变更，不照抄英文提交标题，也不输出“其余 N 条提交”“细节调整和配套修改为主”等折叠占位。提交完整正文参与总结，超出单批数量或字符预算时分批处理；摘要及 Markdown 不再限制为五条，超过报告字符上限时明确报错而非截断。详细规则及发布类改写示例见[周报生成与飞书写入实现思路](./周报生成与飞书写入实现.md#42-业务表达与完整展开)。

每条事项只要包含中文即可，允许保留英文术语、缩写、标识符和版本号，不要求全中文。报告保持中文字段名，账号、仓库、分支及异常信息按原值展示。完全不含中文的提交在生成前过滤；模型若生成完全无中文的事项、空列表或折叠占位，则整次生成失败，不静默省略单条，也不改用本地提交标题。单条完整提交或固定上下文无法放入 prompt 预算时同样失败。完整展开不取消仓库采集上限、AI 响应安全边界或飞书单元格长度策略。
