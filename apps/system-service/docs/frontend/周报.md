# 周报生成模块

## 功能

管理台的“周报生成”菜单迁移源项目的两个 npm 命令：

| 源命令 | 管理台周期 | 行为 |
| --- | --- | --- |
| `week:last` | `last-week` | 统计上一完整周（周一至周日），按工作日合并展示 |
| `week:this` | `this-week` | 统计本周周一至当前日期，按项目展示并生成去重摘要 |

报告会读取各项目的 Git 非合并提交，保留源实现的日期分组、Conventional Commit 前缀清理、集成提交过滤、去重和 Markdown 格式。AI 摘要不可用时自动降级为本地规则摘要。

## 接口

`POST /api/weekly-commit-reports/generate`

请求：

```json
{
  "period": "last-week",
  "configs": [
    {
      "repo": "https://github.com/whtthd/wzj-nodejs-v2.git",
      "person": "ljh",
      "branch": "merge/wzj-temp"
    }
  ]
}
```

`period` 仅支持 `last-week` 和 `this-week`。`configs` 可省略，服务会使用默认仓库配置；每次最多 10 个项目。仓库地址必须命中服务端白名单，本地仓库必须位于允许的本地根目录下。接口不接受输出路径，响应 Markdown 由浏览器负责复制或下载。

响应数据位于统一响应包装的 `data` 字段：

```json
{
  "period": "last-week",
  "weekStart": "2026-08-17",
  "weekEnd": "2026-08-23",
  "markdown": "# ljh 上周任务日志\n...",
  "projects": [],
  "commitCount": 12,
  "degraded": true
}
```

## 配置

配置键定义在 `src/modules/weekly-commit-report/weekly-report.constants.ts` 的 `WeeklyReportConfigKeys` 中，均由 `getConfig` 读取：

- `WeeklyReportAllowedRepositories`：允许访问的 HTTPS 仓库，逗号分隔；未配置时使用迁移的三个默认仓库。
- `WeeklyReportAllowedLocalRoot`：允许访问的本地仓库根目录，默认是服务工作目录。
- `WeeklyReportAiBaseUrl`、`WeeklyReportAiApiKey`、`WeeklyReportAiModel`：服务端 OpenAI-compatible 摘要服务配置。密钥不得写入前端或日志。
- `WeeklyReportCommandTimeoutMs`、`WeeklyReportAiTimeoutMs`：Git 和 AI 请求超时。
- `WeeklyReportMaxProjects`、`WeeklyReportMaxCommits`、`WeeklyReportMaxPromptCommits`、`WeeklyReportMaxPromptCharacters`、`WeeklyReportMaxOutputCharacters`：项目、提交、prompt 和响应大小限制。

## 安全与运行边界

- Git 使用异步参数数组执行，不拼接 shell 命令；仅接受 HTTPS 白名单仓库或允许目录内的本地仓库。
- 远程仓库执行裸 clone 到临时目录，请求结束后清理；Git 和 AI 均有超时与输出限制。
- 服务不写入用户指定路径，也不将提交内容或 AI key 写入日志；AI 失败时使用本地摘要。
- 生产环境应配置仓库白名单，并为 Git 凭据与摘要服务配置最小权限。
