# 周报生成模块

## 功能

管理台的“周报生成”菜单通过 GitHub Commits API 获取项目提交，生成上周或本周的 Markdown 汇总。

| 管理台周期 | 时间范围 | 行为 |
| --- | --- | --- |
| `last-week` | 上一完整周，周一至周日 | 按工作日合并展示 |
| `this-week` | 本周一至当前时刻 | 按项目展示并生成去重摘要 |

服务端先按 `author`、分支和时间窗口请求 GitHub 提交，再过滤 `Merge pull request`、`Merge branch` 和多 parent 合并提交。后续保留原有日期分组、Conventional Commit 前缀清理、去重、AI 摘要和本地规则降级逻辑。

## 接口

`POST /api/weekly-commit-reports/generate`

请求结构不变：

```json
{
  "period": "last-week",
  "configs": [
    {
      "repo": "https://github.com/whtthd/wzj-nodejs-v2.git",
      "person": "2451477516@qq.com",
      "branch": "merge/wzj-temp"
    }
  ]
}
```

异步生成任务可选开启飞书发布：

```json
{
  "period": "last-week",
  "configs": [
    {
      "repo": "https://github.com/whtthd/wzj-nodejs-v2.git",
      "person": "2451477516@qq.com",
      "branch": "merge/wzj-temp"
    }
  ],
  "publish": {
    "enabled": true,
    "person": "张三",
    "settings": {
      "appId": "cli_xxxxxxxxx",
      "appSecret": "<app-secret>",
      "wikiUrl": "https://tthdtech.feishu.cn/wiki/SAxnwUjvZiiGbCk1uvNcZoFCnad?sheet=a0ab9d",
      "name": "张三"
    }
  }
}
```

`publish.settings` 是本次请求的飞书配置，启用时可携带 App ID、App Secret、单个 Wiki 地址和可选姓名；App ID/App Secret 缺失时由服务端按 `FEISHU_CLI_APP_ID`、`FEISHU_CLI_APP_SECRET` 读取环境变量，再回退旧的服务端 Feishu 配置。Wiki 地址必须包含 `?sheet=` 查询参数，服务端固定只读 `A1:B200`，不再接收月份、Sheet ID 或自定义查找范围。`publish.person` 优先于 `settings.name`；两者都未传时，仅在报告结果能推断出唯一人员时允许发布。同步 `POST /generate` 不触发飞书发布，未配置 `publish` 的旧请求行为不变。


```text
GET https://api.github.com/repos/{owner}/{repo}/commits
  ?sha={branch}
  &author={person}
  &since={window.start.toISOString()}
  &until={window.end.toISOString()}
  &per_page=100
  &page=1...
```

`person` 应填写 GitHub login 或提交邮箱。`branch` 为空时不发送 `sha` 参数。每页最多 100 条，服务端按 `WeeklyReportMaxCommits` 分页获取，过滤合并提交后达到上限即停止。

响应仍位于统一响应包装的 `data` 字段：

```json
{
  "period": "last-week",
  "weekStart": "2026-08-17",
  "weekEnd": "2026-08-23",
  "markdown": "# 2451477516@qq.com 上周任务日志\n...",
  "projects": [],
  "projectErrors": [],
  "commitCount": 12,
  "degraded": true,
  "dailySections": []
}
```

页面实际使用异步 Job 接口显示后端进度：

```http
POST /api/weekly-commit-reports/jobs
```

创建后返回 `jobId` 和初始 `progress`。页面随后轮询：

```http
GET /api/weekly-commit-reports/jobs/status?jobId=...
```

进度字段由服务端生成，包括 `phase`、`percent`、`completedProjects`、`totalProjects`、`failedProjects`、`currentProject` 和 `message`。阶段顺序为 `queued`、`validating`、`collecting`、`summarizing`、`finalizing`、`publishing`、`completed`；前端不再使用本地定时器伪造进度。页面提供“同步到飞书文档”复选框，默认不勾选；选择“本周”时该选项置灰，并以 `publish.enabled: false` 提交，避免服务端默认发布配置造成意外写入。选择“上周”并勾选后才会提交 `publish.enabled: true`。任务由固定的 BullMQ 队列 `weekly-report` 使用 `bull` prefix 执行，Worker 并发数为 2，完成或失败任务保留 30 分钟；`publication.status` 单独表示飞书发布的 `skipped`、`succeeded` 或 `failed`，发布失败不会丢失 `markdown`。原 `POST /generate` 同步接口继续保留兼容。

异步任务状态中的飞书字段示例：

```json
{
  "publication": {
    "status": "succeeded",
    "range": "sheet_id!C12:G12",
    "row": 12
  }
}
```

项目配置、飞书同步开关和飞书同步配置保存到 localStorage：

```text
nestcloud:weekly-report:v1
```

草稿中的 `publishSettings` 为单对象，包含 `appId`、`appSecret`、`wikiUrl` 和可选 `name`。`publishEnabled` 缺失或不是 `true` 时按未勾选处理；读取旧版 `monthlyTargets` 草稿时，单项会迁移为单对象，多项会清空目标并要求重新填写，不会自动选择月份。

⚠️ 按当前产品要求，App Secret 会保存到浏览器 localStorage。任何能读取该浏览器存储的脚本、扩展或本机用户都可能获取它，因此只应在受信任的内部管理台和 HTTPS 环境使用，并应定期轮换飞书应用密钥。App Secret 不会写入 BullMQ Job data、Markdown、Job 状态、页面错误消息或服务日志；Worker 仅在当前进程的执行期使用它。

JSON/ENV 两侧输入分别保存到：

```text
nestcloud:compare:json:v1
nestcloud:compare:env:v1
```

存储损坏或不可用时回退到页面默认值，不影响当前页面操作；GitHub Token、飞书 `tenant_access_token` 和服务端 AI 密钥不会写入 localStorage。

## 配置

配置键定义在 `src/modules/weekly-commit-report/weekly-report.constants.ts` 的 `WeeklyReportConfigKeys` 中，普通周报配置通过 `getConfig` 读取：

- `WeeklyReportAllowedRepositories`：允许使用的 GitHub 仓库，逗号分隔；未配置时使用默认仓库。
- `WeeklyReportAiBaseUrl`、`WeeklyReportAiApiKey`、`WeeklyReportAiModel`：服务端 OpenAI-compatible 摘要服务配置。
- `WeeklyReportCommandTimeoutMs`：GitHub API 单次请求超时。
- `WeeklyReportAiTimeoutMs`：AI 摘要请求超时。
- `WeeklyReportMaxProjects`、`WeeklyReportMaxCommits`、`WeeklyReportMaxPromptCommits`、`WeeklyReportMaxPromptCharacters`、`WeeklyReportMaxOutputCharacters`：项目、提交、prompt 和响应限制。

飞书发布配置由页面表单填写，并随异步 Job 的 `publish.settings` 参数传递。页面字段包括：

- `appId`、`appSecret`：飞书自建应用凭据；填写并保存到 localStorage 后优先使用。
- `wikiUrl`：单个 Wiki 或 Sheet 地址，必须通过 URL 的 `?sheet=` 参数指定 Sheet。
- `name`：可选的表格 B 列姓名；也可使用 `publish.person` 覆盖，均未传时从单一项目人员推断。
- 查找范围固定为 `A1:B200`，不作为页面或请求字段传递。

服务端 canonical 配置键为 `WeeklyReportFeishuTarget`，值为单对象。历史 `WeeklyReportFeishuMonthlyTargets` 只用于迁移：单项旧数组会忽略月份和旧范围，并使用固定范围；多项旧数组会报迁移错误，不会静默选择目标。

页面默认保存这些值到 `nestcloud:weekly-report:v1`。如果本地 App ID/App Secret 为空，服务端依次读取 `FEISHU_CLI_APP_ID`、`FEISHU_CLI_APP_SECRET`，再回退旧的 `WeeklyReportFeishuAppId`、`WeeklyReportFeishuAppSecret` 配置。API 请求超时和临时错误重试次数由服务端配置控制，不从页面传递。

示例（请将 Sheet ID 放在 URL 的 `sheet` 查询参数中）：

```json
{
  "wikiUrl": "https://tthdtech.feishu.cn/sheets/ZVPMsdbHphQOdetitZbcMu7NnEd?sheet=a0ab9d",
  "name": "张三"
}
```

发布使用 `last-week` 的五个工作日摘要：固定只读 `A1:B200`，按 `8.24-8.28` 这类日期范围和姓名精确匹配唯一行；如果日期列使用纵向合并单元格，后续返回的 `null` 行会沿用最近一个非空日期范围。找到目标行后再读取该行 `C:G`，同一单元格内的多条摘要按 `1. `、`2. ` ` 等序号逐行写入。内容相同返回 `publication.status=skipped`；内容变化时只更新 `C{row}:G{row}`，不会清空或改动其它单元格。零行、多行、非 Sheet、权限不足或目标配置缺失均不会发起写入。`this-week` 暂不自动发布。

GitHub Token 不从项目 `.env` 读取，只从运行 system-service 的电脑系统环境变量读取，页面请求不会接收 GitHub Token：

```text
GITHUB_TAG_FILE_TOKEN
```

页面不会接收或保存 GitHub Token、飞书 `tenant_access_token`；仅在勾选同步且 localStorage 中存在时提交 App ID/App Secret。

## 错误与运行边界

- GitHub URL、仓库白名单、字段格式和全局 Token 校验失败时，整份请求仍返回错误。
- 单个项目的 GitHub API 401、403、404、422、429、网络错误或超时会写入 `projectErrors`，跳过该项目并继续读取后续项目。
- `projects`、`commitCount` 和上周报告的 `Sources` 只包含成功读取的项目。
- `projectErrors` 始终是数组，每项包含 `repo`、`repoLabel`、`code` 和 `message`；异常也会追加到 Markdown 的“项目异常”区块。
- `degraded` 仍只表示 AI 摘要不可用时使用本地规则摘要。
- 生产环境应通过受控管理网络或反向代理保护接口，并配置 GitHub API 速率限制。
