# 前端管理台实现逻辑

## 静态服务注册

`apps/system-service/src/app.module.ts` 使用 `ServeStaticModule.forRoot` 注册静态服务：

- `rootPath` 指向编译后的 `dist/public`，通过 `join(__dirname, 'public')` 解析。
- `serveRoot` 为 `/public`，因此入口地址为 `/public/index.html`。
- 公共启动器继续由 `apps/common-service` 提供，`system-service` 不重复配置 Express 中间件。

## 资源构建

`apps/system-service/nest-cli.json` 在 `compilerOptions.assets` 中配置 `../public/**/*`，将项目根目录下的 `public` 资源复制到 `dist/public`。`assets` 必须位于 `compilerOptions` 内，否则 Nest CLI 不会执行复制。

## 页面文件职责

- `public/index.html`：工作台页面骨架、主导航、主体视图和可访问性属性。
- `public/css/app.css`：设计令牌、桌面/移动布局、组件状态和动效约束。
- `public/js/app.js`：总览 hash 规范化、移动端抽屉和键盘关闭逻辑。

浏览器脚本在 Node 环境检测到 `document` 不存在时立即退出。这样可以避免共享自动注册器扫描 `dist` 时误加载浏览器脚本。

## 内容扩展

新增业务页面时：

1. 在 `index.html` 增加对应 `data-view` 主体和导航链接。
2. 在 `app.js` 中同步登记合法 hash、标题和活动状态处理。
3. 在 `app.css` 中复用现有设计令牌，不直接散落新的颜色、间距或圆角值。
4. 业务数据通过正式接口接入，不在静态页面中伪造请求结果。
