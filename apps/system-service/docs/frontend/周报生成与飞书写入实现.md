# 周报生成与飞书写入实现思路

## 1. 范围

本文只描述以下三部分业务及其使用的接口：

1. 获取 Git 提交记录。
2. 使用 AI 对提交记录进行总结。
3. 将总结结果写入飞书表格。

不展开管理台页面、任务队列、通用权限模型或其它外部设计。运行时的详细时序请参阅《[周报生成与飞书写入流程](./周报生成与飞书写入流程.md)》。

## 2. 总体业务链路

周报处理按以下顺序执行：

1. 根据周报周期确定 Git 提交时间范围。
2. 按项目获取 Git 提交记录。
3. 清洗提交记录并按日期整理。
4. 将整理后的提交发送给 AI，生成日报或项目摘要。
5. AI 不可用时使用本地规则生成摘要。
6. 发布条件满足时解析飞书 Wiki 和 Sheet。
7. 在固定的 `A1:B200` 范围内按日期范围和姓名查找目标行。
8. 将五个工作日摘要映射到目标行 `C:G`，比较后按需更新。

## 3. 获取 Git 提交记录

### 3.1 使用的接口

**GitHub Commits API**

- 接口：`GET https://api.github.com/repos/{owner}/{repo}/commits`
- 使用位置：`WeeklyCommitReportService`
- 请求参数：仓库、分支、提交人、开始时间、结束时间和分页参数。
- 认证信息：服务端环境变量 `GITHUB_TAG_FILE_TOKEN`。

### 3.2 调用流程

调用 GitHub 接口前：

- 校验仓库地址为无凭据的 GitHub HTTPS 地址。
- 校验仓库是否位于 `WeeklyReportAllowedRepositories` 白名单。
- 根据 `period` 计算时间范围：`last-week` 为上一完整周，`this-week` 为本周至当前时间。
- 按项目数、提交数、分页次数和请求超时限制执行读取。

调用接口后：

- 分页获取提交记录。
- 丢弃缺少哈希、时间或提交消息的记录。
- 丢弃 `Merge pull request`、`Merge branch` 等合并提交。
- 丢弃拥有多个 parent 的合并提交。
- 按作者名称、GitHub login、提交邮箱或项目配置补全作者信息。
- 将提交消息拆分为标题和正文，形成统一的 Git 提交记录。
- 按日期整理为日报输入。
- 单个项目失败时记录 `projectErrors`，继续读取其它项目。

### 3.3 输出数据

Git 提交处理阶段输出：

- 仓库和分支信息。
- 项目提交数量。
- 清洗后的提交记录。
- 按日期分组的提交记录。
- 项目读取异常。

这些数据作为 AI 总结阶段的输入，也作为本地规则摘要的输入。

## 4. AI 总结提交记录

### 4.1 使用的接口

**OpenAI-compatible Chat Completions 接口**

- 接口地址：由 `WeeklyReportAiBaseUrl` 配置。
- 使用位置：`WeeklyCommitReportService.requestAiSummary()`。
- 配置项：`WeeklyReportAiBaseUrl`、`WeeklyReportAiApiKey`、`WeeklyReportAiModel`。
- 输入内容：已清洗的提交日期、作者、标题、正文、项目和报告周期。
- 输出内容：日报或项目摘要。

### 4.2 调用流程

- 根据当前报告阶段组装提交摘要请求。
- 传入项目、日期和提交记录上下文。
- 校验 AI 返回内容和输出格式。
- 限制提交数量、输入字符数、输出字符数和 AI 请求超时。
- 将有效摘要转换为日报或项目结果中的 `bullets`。

AI 只处理已经确认的 Git 提交记录，不负责仓库筛选、日期计算、人员匹配或飞书表格写入。

### 4.3 本地规则降级

以下情况使用本地规则摘要：

- AI 地址或密钥未配置。
- AI 请求超时。
- AI 服务不可用。
- AI 返回空内容。
- AI 返回内容无法解析或不符合要求。

本地规则以清洗后的提交标题为基础，并处理 Conventional Commit 前缀等技术噪声。`degraded` 用于标记本次摘要是否使用降级路径。

## 5. 写入飞书表格

### 5.1 使用的接口

| 接口                                                                      | 用途                              |
| ------------------------------------------------------------------------- | --------------------------------- |
| `POST /open-apis/auth/v3/tenant_access_token/internal`                    | 获取飞书租户访问令牌              |
| `GET /open-apis/wiki/v2/spaces/get_node`                                  | 将 Wiki 节点解析为 Sheet 对象     |
| `GET /open-apis/sheets/v3/spreadsheets/{spreadsheetToken}/sheets/query`   | 查询目标电子表格中的 Sheet 列表   |
| `GET /open-apis/sheets/v2/spreadsheets/{spreadsheetToken}/values/{range}` | 读取日期/姓名区域和目标行当前内容 |
| `PUT /open-apis/sheets/v2/spreadsheets/{spreadsheetToken}/values`         | 更新目标行的五个工作日单元格      |

### 5.2 获取访问令牌

**接口**：`POST /open-apis/auth/v3/tenant_access_token/internal`

处理内容：

- 使用 App ID 和 App Secret获取 `tenant_access_token`。
- 按应用凭据缓存令牌。
- 令牌过期时重新获取。
- 收到 401 时清理缓存并刷新一次。

凭据来源依次为请求级配置、`FEISHU_CLI_APP_ID`/`FEISHU_CLI_APP_SECRET`，以及旧服务端飞书凭据配置。

### 5.3 解析 Wiki 或 Sheet 地址

**接口**：`GET /open-apis/wiki/v2/spaces/get_node`

当配置为 Wiki 地址时：

1. 从 URL 获取 Wiki 节点 token。
2. 查询 Wiki 节点详情。
3. 确认节点类型为 Sheet。
4. 获取实际的 spreadsheet token。
5. 从 URL 的 `?sheet=<sheetId>` 获取具体 Sheet ID。

当配置为 `/sheets/<spreadsheetToken>?sheet=<sheetId>` 地址时，直接使用 spreadsheet token，不查询 Wiki 节点。

### 5.4 校验 Sheet

**接口**：`GET /open-apis/sheets/v3/spreadsheets/{spreadsheetToken}/sheets/query`

- 获取当前电子表格的 Sheet 列表。
- 检查 URL 中的 `sheetId` 是否存在。
- Sheet 不存在时停止当前发布，不读取表格值。

### 5.5 读取表格值

**接口**：`GET /open-apis/sheets/v2/spreadsheets/{spreadsheetToken}/values/{range}`

读取两个范围：

- 查找区域：`<sheetId>!A1:B200`。
- 目标内容：`<sheetId>!C<row>:G<row>`。

查找区域固定为 `A1:B200`，不从请求参数读取范围。

### 5.6 查找目标行

在 A1:B200 的返回值中：

- 将周一和周五日期转换为 `MM-DD` 日期范围。
- 兼容点号、中文“至”、不同横线和空格等日期写法。
- 日期列为空时沿用前一个非空日期，支持纵向合并单元格。
- 对姓名执行 Unicode 归一化、空白折叠和首尾空格清理。
- 要求日期范围和姓名同时匹配。
- 零条匹配或多条匹配时停止发布。
- 只有唯一匹配时计算目标行号。

姓名来源优先级：

1. `publish.person`。
2. `publish.settings.name`。
3. 成功项目中的唯一提交人。

### 5.7 生成 C:G 内容

五个工作日摘要依次对应目标行的 C、D、E、F、G 列：

- 每天的多条摘要按序号排列。
- 没有事项时使用“无新增事项”。
- 清理换行和多余空白。
- 限制单元格内容长度。
- 对以 `=`, `+`, `-`, `@` 开头的内容做公式前缀防护。

### 5.8 比较并更新

**接口**：`PUT /open-apis/sheets/v2/spreadsheets/{spreadsheetToken}/values`

执行顺序：

1. 读取目标行 C:G 当前值。
2. 将当前值与五个工作日摘要逐格比较。
3. 五格完全相同：返回 `skipped`，不调用 PUT。
4. 存在差异：只调用 PUT 更新 `<sheetId>!C<row>:G<row>`。

A:B 定位数据、其它行、其它列和整张表不会被修改。

## 6. 三部分业务边界

### Git 提交记录

负责仓库、分支、提交人、时间窗口、提交获取、提交清洗和日报输入整理。

### AI 总结

负责将已确认的提交记录整理为可读摘要，以及 AI 不可用时的本地规则降级。

### 飞书写入

负责 Wiki/Sheet 解析、目标行匹配、五日摘要映射、内容比较和 C:G 更新。

三部分之间通过结构化的提交记录、日报摘要和报告结果传递数据，不互相承担对方的职责。

## 7. 失败处理

- GitHub 单项目失败：记录项目错误，继续其它项目。
- AI 失败：使用本地规则摘要，报告继续生成。
- Wiki 解析失败：停止飞书发布。
- Sheet 不存在：停止飞书发布。
- 日期或姓名零行/多行匹配：停止发布，不执行 PUT。
- 飞书读取失败：停止当前发布。
- 飞书更新失败：报告结果保留，发布结果标记失败。
- C:G 内容未变化：返回跳过，不产生更新请求。

外部接口的超时、有限重试和错误脱敏由对应客户端统一处理。
