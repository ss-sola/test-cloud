# 周报生成与飞书写入实现思路

## 1. 范围

本文只描述以下三部分业务及其使用的接口：

1. 获取 Git 提交记录。
2. 使用 AI 对提交记录进行总结。
3. 将总结结果写入飞书表格。

不展开管理台页面、任务队列、通用权限模型或其它外部设计。运行时的详细时序请参阅《[周报生成与飞书写入流程](./周报生成与飞书写入流程.md)》。

## 2. 总体业务链路

周报处理按以下顺序执行：

1. 根据周报周期确定 Git 提交时间范围。
2. 按项目获取 Git 提交记录。
3. 清洗提交记录并按日期整理。
4. 将整理后的提交发送给 AI，生成日报或项目摘要。
5. AI 不可用时使用本地规则生成摘要。
6. 发布条件满足时解析飞书 Wiki 和 Sheet。
7. 在固定的 `A1:B200` 范围内按日期范围和姓名查找目标行。
8. 将五个工作日摘要映射到目标行 `C:G`，比较后按需更新。

## 3. 获取 Git 提交记录

### 3.1 使用的接口

**GitHub Commits API**

- 接口：`GET https://api.github.com/repos/{owner}/{repo}/commits`
- 使用位置：`WeeklyCommitReportService`
- 请求参数：仓库、分支、提交人、开始时间、结束时间和分页参数。
- 认证信息：由本次请求 `runtime.githubToken` 提供。

### 3.2 调用流程

调用 GitHub 接口前：

- 校验仓库地址为无凭据的 GitHub HTTPS 地址。
- 校验仓库是否位于本次请求 `runtime.allowedRepositories` 白名单；未提供白名单时只使用请求中的项目列表。
- 根据 `period` 计算时间范围：`last-week` 为上一完整周，`this-week` 为本周至当前时间。
- 按项目数、提交数、分页次数和请求超时限制执行读取。

调用接口后：

- 分页获取提交记录。
- 丢弃缺少哈希、时间或提交消息的记录。
- 丢弃 `Merge pull request`、`Merge branch` 等合并提交。
- 丢弃拥有多个 parent 的合并提交。
- 按作者名称、GitHub login、提交邮箱或项目配置补全作者信息。
- 将提交消息拆分为标题和正文，形成统一的 Git 提交记录。
- 在生成摘要前统一去掉提交类型前缀，剔除空标题、纯合并/同步集成记录以及标题和完整正文均相同的重复记录。
- 相同标题但正文不同的提交分别保留；标题或完整正文只要有中文就保留，允许中英混写，完全不含中文的记录在生成摘要前过滤。
- 过滤后的记录统一用于提交数量统计、模型输入和本地摘要，之后再按日期整理为日报输入。
- 单个项目失败时记录 `projectErrors`，继续读取其它项目。

### 3.3 输出数据

Git 提交处理阶段输出：

- 仓库和分支信息。
- 项目提交数量。
- 清洗后的提交记录。
- 按日期分组的提交记录。
- 项目读取异常。

这些数据作为 AI 总结阶段的输入，也作为本地规则摘要的输入。

## 4. AI 总结提交记录

### 4.1 使用的接口

**OpenAI-compatible Chat Completions 接口**

- 接口地址：由本次请求 `runtime.ai.baseUrl` 提供。
- 使用位置：`WeeklyCommitReportService.requestAiSummary()`。
- 配置项：本次请求 `runtime.ai.baseUrl`、`runtime.ai.apiKey`、`runtime.ai.model`。
- 输入内容：已清洗的提交日期、作者、标题、正文、项目和报告周期。
- 输出内容：日报或项目摘要。

### 4.2 业务表达与完整展开

日报和项目周报使用同一组业务表达规则，每条说明“业务对象 + 具体变更”，只有提交记录提供依据时才补充作用或结果。每条事项只要包含中文即可，允许中英混写，SQL、API、AI 等术语、必要标识符和 v1.12.0 等版本号可以保留；不再执行全中文或禁止英文缩写的校验，不输出完全不含中文的事项。

报告标题及可读字段使用中文字段名，人员、仓库、分支和异常详情保留原始值，允许其中包含英文，不再因语言要求隐藏原始信息，也不猜测中文名称。

发布类记录也应描述具体交付对象，例如：

- `update release artifacts for 1.12.0`：更新 1.12.0 版本发布产物。
- `exclude classroom note configs from v1.12.0`：从 1.12.0 发布配置中排除课堂笔记相关配置。
- `release: release version 1.12.0`：发布 1.12.0 版本；不能据此推断已部署到生产、功能已上线或验证通过。
- `add data platform SQL and school release env for 1.12.0`：分别列出“补充 1.12.0 数据平台数据库脚本”和“补充 1.12.0 学校发布环境配置”。

示例只约束表达方式，不是本次工作事实。实际内容必须来自本批提交标题和正文，不能依据仓库名称或版本号虚构业务收益。

完整展开规则：

- 不再要求每组 2–5 条，也不为了满足固定条数而编造或压缩内容。
- 一条提交中的不同业务事项分别列出；不同业务对象、条件或行为变化不得折叠到一条。
- 仅对重复工作成果去重，不以“其余 N 条提交”“工作未展开”“细节调整和配套修改为主”代替实际事项。
- 本地摘要、AI 列表清洗、工作日分配、项目摘要和 Markdown 渲染均不再设置五条限制，超过 25 条工作也完整分配到五个工作日。
- AI 返回“其余/剩余 N 条提交、工作或事项”类占位时，该批结果视为无效，使用该批次本地摘要，避免接受已明确折叠的输出。

### 4.3 调用流程与长度边界

- 根据日报或项目周报阶段组装提示词，使用统一业务规则。
- 每条提交以 JSON 数据提供日期、作者、标题及完整正文，不再只读取正文第一行；提交数据不作为模型指令。
- 按 `maxPromptCommits` 和完整提示词的 `maxPromptCharacters` 分批，字符预算包含写作规则、示例、历史事项和提交数据，不再直接丢弃超出单批数量的提交。
- 依次总结所有批次，对全部批次结果去重，不追加“剩余提交”条目。
- 单条完整正文或固定规则及历史上下文无法装入提示词时，使用该批次本地摘要并标记 `degraded`，不因其中含有英文术语而报错。
- AI 请求仍有超时及响应字符数上限；校验失败或请求失败时仅降级对应批次。
- Markdown 超过 `runtime.limits.maxOutputCharacters` 时抛出 422 异常，提示提高该上限后重试，不返回截断报告。

完整展开针对已采集范围内的工作事项，不取消 `maxCommitsPerRepository` 的仓库采集上限，也不承诺模型必然识别全部业务细节。飞书单元格仍沿用原有 `FEISHU_MAX_CELL_CHARACTERS`（8,000 字符）长度处理，与 Markdown 输出上限分别管理。

AI 只处理已经确认的 Git 提交记录，不负责仓库筛选、日期计算、人员匹配或飞书表格写入。

### 4.4 本地规则降级

以下情况使用本地规则摘要：

- AI 地址或密钥未配置。
- AI 请求超时。
- AI 服务不可用。
- AI 返回空内容。
- AI 返回内容无法解析或不符合要求。

本地规则优先使用含中文的提交标题；中文仅在正文时，使用完整正文并整理换行和多余空白，不只取第一行。允许中英混写，不再因英文术语、缩写或字母版本号抛出全中文校验错误。`degraded` 标记本次摘要是否使用降级路径。模型列表中出现完全不含中文的事项时，整批降级，保留该批次可用的本地事项，不静默删除单条模型输出。完全无中文的原始提交已在生成前过滤。

## 5. 写入飞书表格

### 5.1 使用的接口

| 接口                                                                      | 用途                              |
| ------------------------------------------------------------------------- | --------------------------------- |
| `POST /open-apis/auth/v3/tenant_access_token/internal`                    | 获取飞书租户访问令牌              |
| `GET /open-apis/wiki/v2/spaces/get_node`                                  | 将 Wiki 节点解析为 Sheet 对象     |
| `GET /open-apis/sheets/v3/spreadsheets/{spreadsheetToken}/sheets/query`   | 查询目标电子表格中的 Sheet 列表   |
| `GET /open-apis/sheets/v2/spreadsheets/{spreadsheetToken}/values/{range}` | 读取日期/姓名区域和目标行当前内容 |
| `PUT /open-apis/sheets/v2/spreadsheets/{spreadsheetToken}/values`         | 更新目标行的五个工作日单元格      |

### 5.2 获取访问令牌

**接口**：`POST /open-apis/auth/v3/tenant_access_token/internal`

处理内容：

- 使用 App ID 和 App Secret获取 `tenant_access_token`。
- 按应用凭据缓存令牌。
- 令牌过期时重新获取。
- 收到 401 时清理缓存并刷新一次。

凭据只来自本次请求 `publish.settings.appId`/`appSecret`，不读取 CLI 环境变量或旧服务端配置。

### 5.3 解析 Wiki 或 Sheet 地址

**接口**：`GET /open-apis/wiki/v2/spaces/get_node`

当配置为 Wiki 地址时：

1. 从 URL 获取 Wiki 节点 token。
2. 查询 Wiki 节点详情。
3. 确认节点类型为 Sheet。
4. 获取实际的 spreadsheet token。
5. 从 URL 的 `?sheet=<sheetId>` 获取具体 Sheet ID。

当配置为 `/sheets/<spreadsheetToken>?sheet=<sheetId>` 地址时，直接使用 spreadsheet token，不查询 Wiki 节点。

### 5.4 校验 Sheet

**接口**：`GET /open-apis/sheets/v3/spreadsheets/{spreadsheetToken}/sheets/query`

- 获取当前电子表格的 Sheet 列表。
- 检查 URL 中的 `sheetId` 是否存在。
- Sheet 不存在时停止当前发布，不读取表格值。

### 5.5 读取表格值

**接口**：`GET /open-apis/sheets/v2/spreadsheets/{spreadsheetToken}/values/{range}`

读取两个范围：

- 查找区域：`<sheetId>!A1:B200`。
- 目标内容：`<sheetId>!C<row>:G<row>`。

查找区域固定为 `A1:B200`，不从请求参数读取范围。

### 5.6 查找目标行

在 A1:B200 的返回值中：

- 将周一和周五日期转换为 `MM-DD` 日期范围。
- 兼容点号、中文“至”、不同横线和空格等日期写法。
- 日期列为空时沿用前一个非空日期，支持纵向合并单元格。
- 对姓名执行 Unicode 归一化、空白折叠和首尾空格清理。
- 要求日期范围和姓名同时匹配。
- 零条匹配或多条匹配时停止发布。
- 只有唯一匹配时计算目标行号。

姓名来源优先级：

1. `publish.person`。
2. `publish.settings.name`。
3. 成功项目中的唯一提交人。

### 5.7 生成 C:G 内容

五个工作日摘要依次对应目标行的 C、D、E、F、G 列：

- 每天的多条摘要按序号排列。
- 没有事项时使用“无新增事项”。
- 清理换行和多余空白。
- 限制单元格内容长度。
- 对以 `=`, `+`, `-`, `@` 开头的内容做公式前缀防护。

### 5.8 比较并更新

**接口**：`PUT /open-apis/sheets/v2/spreadsheets/{spreadsheetToken}/values`

执行顺序：

1. 读取目标行 C:G 当前值。
2. 将当前值与五个工作日摘要逐格比较。
3. 五格完全相同：返回 `skipped`，不调用 PUT。
4. 存在差异：只调用 PUT 更新 `<sheetId>!C<row>:G<row>`。

A:B 定位数据、其它行、其它列和整张表不会被修改。

## 6. 三部分业务边界

### Git 提交记录

负责仓库、分支、提交人、时间窗口、提交获取、提交清洗和日报输入整理。

### AI 总结

负责将已确认的提交记录整理为可读摘要，以及 AI 不可用时的本地规则降级。

### 飞书写入

负责 Wiki/Sheet 解析、目标行匹配、五日摘要映射、内容比较和 C:G 更新。

三部分之间通过结构化的提交记录、日报摘要和报告结果传递数据，不互相承担对方的职责。

## 7. 失败处理

- GitHub 单项目失败：记录项目错误，继续其它项目。
- AI 失败：使用包含中文的本地摘要，允许中英混写，报告继续生成。
- Wiki 解析失败：停止飞书发布。
- Sheet 不存在：停止飞书发布。
- 日期或姓名零行/多行匹配：停止发布，不执行 PUT。
- 飞书读取失败：停止当前发布。
- 飞书更新失败：报告结果保留，发布结果标记失败。
- C:G 内容未变化：返回跳过，不产生更新请求。

外部接口的超时、有限重试和错误脱敏由对应客户端统一处理。
