# 节点扩展

## 分层与业务文档协议

`public/js/workflow-core.js` 在浏览器导出 `window.NestCloudWorkflowCore`，在 Node 环境导出 `module.exports`；`public/js/workflow-nodes.js` 对应导出 `NestCloudWorkflowNodes` / `module.exports`。`NodeRegistry` 管理受控节点实现和数据类型，`Workspace` 管理文档、历史与运行，画布库 X6 只负责视图交互。用户文档只引用**已注册的实现**，不得携带执行代码、任意请求地址或 X6 私有序列化字段。

```json
{
  "version": 1,
  "id": "flow-1",
  "name": "对比示例",
  "nodes": [
    {
      "id": "input-a",
      "type": "text",
      "version": 1,
      "name": "A 文本",
      "position": { "x": 40, "y": 40 },
      "size": { "width": 320, "height": 280 },
      "config": { "text": "hello" }
    }
  ],
  "edges": [],
  "viewport": { "x": 24, "y": 24, "zoom": 1 }
}
```

节点字段仅为 `id/type/version/name/position/size/config`；边为 `{id,source:{nodeId,port},target:{nodeId,port}}`；文档为 `{version:1,id,name,nodes,edges,viewport:{x,y,zoom}}`。`parseDocument` 重新校验、规范化且仅保留这些白名单字段，不依赖 X6 图对象。文档格式 `version` 与节点实现 `type + version` 是两层不同版本：格式不兼容则拒绝；格式合法但节点类型或版本未注册时，保留其受限 JSON 配置及连线供查看/导出，**不能运行整图**，也不退回到当前版本的执行器。不要把导入的节点版本静默升级；需要迁移时提供显式迁移方案。文档解析对已注册节点调用 `validateConfig`，未知版本只做通用 JSON 深度与结构校验。

## 注册类型、端口与版本

- `registry.registerDataType(name, validate, { base? })` 注册全局唯一的数据类型名和运行时校验器；已有 `text` 类型校验字符串长度不超过 500000，内置节点再注册值必须为 `true` 的 `trigger`、结构化 `diff` 和由 workflow-data 校验的有界 `json` 类型。json 用于原子能力间的对象/数组数据，仍与 text 精确区分，文本转 JSON 必须显式经过 json-parse。`base` 声明该类型是某个已注册基类型的语义子类型（仅一层，子类型不能再作基类型），原子能力据此注册 date-range、commit-list、match-list、sheet-target、cell-matrix 五个 json 子类型。新增类型**先注册后用于端口**，类型名须符合标识符约束；校验器返回布尔值。连线由 `registry.compatible(output, input)` 判定：类型相同，或一方是另一方的子类型时相容，同一基类型下的不同子类型互斥；`kind` 必须精确相等（省略时为 `data`），不做自动转换。类型不同但相容的连线（例如 json → cell-matrix）在运行时先用**输入端口**类型的校验器检查实际值，不合格则该节点失败且不调用执行器。需要语义转换时注册显式转换节点。
- `registry.register({ type, version, label, category, execution?, inputs, outputs, defaults, size, validateConfig, execute, render })` 注册一个确切节点版本。`execution` 是注册元信息，取 `entry`（入口）、`data`（被动数据来源）或 `task`（处理／展示，默认）；不从文档节点的 `type` 名称或配置猜测角色。`entry/data` 不允许声明输入，`entry` 至少声明一个输出。`type` 和每组端口 `id` 有格式/唯一性约束；`version` 为正安全整数，同一 `type@version` 不得重复；`execute` 必填，`render` 为 UI 可选。`inputs`、`outputs` 中的端口为 `{id,label,dataType,kind?,required?}`；`kind` 为 `data`（默认）或 `control`，`required` 用于输入必填检查，输出声明的端口都必须返回有效值。`defaults` 用于新建节点的初始配置；`size` 用于初始尺寸；`validateConfig(config)` 通过时返回 `null`（或其他假值），错误时返回可展示的错误字符串。校验不要悄悄补齐旧文档的必需业务配置。可选 `migrate(config)` 把**上一版本**的配置转换为本版本配置，可选 `renameInputs: { 旧端口: 新端口 }` 在升级时把指向该节点的连线改接新输入端口，二者供显式升级使用。
- `registry.get(type, version)` 只查精确版本；`registry.list()` 每类只列已注册的最高版本，新建节点使用它的 defaults 和 size。新增 `version: 2` 时仍应保留 `version: 1` 的实现以便旧流程继续运行，或允许旧流程作为未知版本保留但不可运行；注册新版本不会自动修改已有流程。`workspace.upgradeNode(nodeId, documentId?)` 从节点当前版本起逐版本调用 `migrate`，把节点改为最新版本并作为一次可撤销编辑提交（重新经过新版本 `validateConfig` 和连线校验）；已是最新或任一中间版本缺少 `migrate` 时拒绝且不修改文档。画布在旧版本节点上显示“升级到 vN”入口，版本变化后整体重建该节点视图。`parseDocument` 在导入、恢复及编辑提交时统一限制每份文档**最多一个已注册的 `entry`**；添加第二个入口、复制所选入口、插入含入口的子图或导入重复入口均原子拒绝。整份工作流复制可保留原入口；旧 v1 无入口文档可恢复/编辑，不自动补入口或改格式，运行时必须恰有一个有出边的入口。未知类型/版本仍可保留受限配置与连线供查看、导出，但会阻止整图运行。
- `execute({ node, inputs, controls, services, signal, suspend })` 返回（也可异步返回）`{ [outputPortId]: value }`。`node` 是运行时不可变文档快照，`inputs` 仅含 data 端口值，`controls` 单独包含 control 端口值，两者均只读且按端口 id 索引；业务处理从 `inputs` 读取 A/B 等数据，不从控制信号读取业务原文。**空字符串是有效值**，缺失按是否拥有自身键判断。`services` 是宿主注入的受控能力，例如 `services.compare({format,left,right,signal})`；`signal` 用于协作取消。`suspend(work)` 用于等待人工确认等非计算阶段：调用时归还工作区执行名额，`work()` 结束后重新排队取得名额再继续，取消时照常中止；飞书写入确认即通过它等待，纯计算或远程请求不要使用。执行器不直接修改节点、画布、其他分支或 `localStorage`，不在返回对象内携带 UI 状态。核心验证所有声明的输出端口均存在且通过类型校验，并冻结可分发的 JSON 数据，避免分支间相互修改。额外输出键不用于下游分发。入口先执行并成功后，才调度从其出边可达的节点及被动数据依赖；数据边也可激活下游任务，范围外任务不因数据依赖而自动运行。

例如，若后续确需限长文本类型，开发者可先注册 `registry.registerDataType('short-text', value => typeof value === 'string' && value.length <= 1000)`，再在新节点端口上使用 `dataType: 'short-text'`；它不会自动连接到 `text` 输入。需让两者互通时应定义显式转换节点，而非关闭连线类型检查。

### 分类路径与节点搜索

`category` 使用 `/` 表示多级目录，例如 `内容处理/文本`；省略或空分类归入“其他节点”。各级目录按首次出现顺序生成，同目录叶子按注册顺序展示。目录来自注册表，不需要在画布内添加分类判断或硬编码节点列表。

`workflow-palette.js` 仅索引 label、type、category 和输入/输出端口的 id、label、dataType。它不索引 defaults 或用户输入、不调用执行器或渲染器、不修改定义。新增节点正确填写这些元信息后会自动参与文件夹展示和搜索。分类名及节点名使用安全文本 API 展示，不解释为 HTML。

## 扩展示例：文本去两端空格

以下片段用于**已加载** `workflow-core.js` 和 `workflow-nodes.js` 的浏览器开发环境中注册节点，不执行示例或自动加入现有画布；正式接入时将注册调用加入 `workflow-nodes.js` 的 `createRegistry` 返回前，或在该位置调用独立模块的注册函数，不需要修改画布核心。须在 UI 创建 `Workspace` **之前**把同一节点定义注册到 UI 所用的 registry，并确保该 registry 的渲染器被画布代理调用。这里使用内置 `text` 和 `trigger` 数据类型（由内置 registry 提供），为例子提供专属的只读结果 renderer，不借用内置文本编辑器，也不开放用户在线脚本。

```js
const registry = window.NestCloudWorkflowNodes.createRegistry()
registry.register({
  type: 'trim-text', version: 1, label: '文本去空格', category: '文本处理',
  inputs: [
    { id: 'trigger', label: '启动', dataType: 'trigger', kind: 'control' },
    { id: 'text', label: '原文', dataType: 'text', required: true },
  ],
  outputs: [{ id: 'text', label: '去空格文本', dataType: 'text' }],
  defaults: {}, size: { width: 280, height: 180 },
  validateConfig: (config) => Object.keys(config).length ? '此节点无需配置。' : null,
  execute: ({ inputs, signal }) => {
    if (signal.aborted) throw new Error('运行已停止。')
    return { text: inputs.text.trim() }
  },
  render: ({ body }) => {
    const output = document.createElement('pre')
    body.append(output)
    return {
      update: ({ state }) => { output.textContent = state?.outputs?.text ?? '' },
      destroy: () => output.remove(),
    }
  },
})
```

作为根任务时，将唯一开始节点的 `trigger` 控制输出连到此节点可选的 `trigger` 输入，并将被动文本节点的 `text` 数据输出连到 `text` 输入；运行从 `entry` 开始，控制信号位于只读 `controls` 而非业务 `inputs`，示例的 `execute` 仅处理文本。其数据输出也可继续连接下游数据输入以激活后续节点。若仅作为已有活动分支的下游处理步骤，数据边也可使它进入可达范围，不要求每个任务都有独立的控制连线。示例 `render` 只创建展示元素，`update` 使用 `textContent` 输出安全文本；真实 UI 可提供适合该节点的编辑控件，通过 `workspace.updateNode` 写入配置，而不是直接改 `node`。若复用已有 renderer，必须确认其读写的端口/配置字段与新定义兼容，不能仅因样式相似就直接套用。

## render 与画布代理的契约

`render({ node, body, workspace, runtime, documentId })` 由画布代理调用，可以不返回（静态内容，如内置开始节点），也可以返回 `{ update({node,state,locked}), flush?(), destroy?() }`。通用节点壳负责开始节点的名称和运行状态。`flush` 用于在运行、切换或离页前提交防抖编辑；无待提交内容的展示节点可以不提供。`documentId` 固定视图所属流程，编辑命令应显式传入，避免切换后写入其他流程。`body` 是节点内容容器；`node` 是当前文档节点；`workspace` 提供命令和订阅；`runtime` 为该流程运行状态。提供 `update` 时，它接收最新节点、节点执行 `state`（含 `status/message/outputs`）和运行锁 `locked`，仅同步视图；`destroy` 在视图释放时清理 DOM/监听器。渲染器**不得**修改冻结文档或运行状态，文本/配置变化走 `Workspace.updateNode`，连线走 `Workspace.connect`/`disconnect`。如果自定义 UI 需要事件监听，卸载时解除订阅，避免切换工作流后仍把旧结果画入新节点。内置 `createRegistry(renderers)` 接收 `start/compare/result` 三个专用 renderer，以及 `capability/textResult` 两个通用 renderer；文本节点不再使用专用编辑器，与原子能力一样由 `capability` 按声明式 fields 渲染。注册表本身不负责 DOM 挂载。受控定义可声明 fields 元信息（key/label/type/options/min/max/rows/help/placeholder；type 取 text/textarea/number/select/checkbox/date，其中 date 为可手输的文本框加暗色月历浮层（挂在 body 上的 .workflow-view 浮层，同一时刻只打开一个，节点锁定或销毁时关闭），值仍是字符串，以及文本域的 `fill` 占满节点剩余高度、文本类字段的 `counter` 字数提示），通用 renderer 据此生成表单，不从导入配置生成控件或执行代码；定义上的 `preview: false` 隐藏输出预览（如文本节点的输出即自身配置），`remote: true` 表示配置固定含 `credentialRef:'token-config'` 并显示凭据来源说明，该键不作为表单字段。原子能力的允许配置键由 fields（及 remote）推导，字段规则写在同一定义的 `check` 中，不再维护单独的键清单。远程服务还可由宿主注入 confirmWrite({wikiUrl,range,values,signal,nodeName})，仅用于每次写入的实际内容确认，不成为文档配置。

`Workspace` 会发出 `(documentId, {kind,nodeIds?})` 事件；UI 按归属及事件类型局部更新。开发者新增节点时同时给出配置校验、输入/输出类型和结果展示，并覆盖缺失输入、错误输出、取消及旧版本载入等场景；不要把执行代码写入用户导出的 JSON。
