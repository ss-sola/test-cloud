# 执行与存储

## 执行入口和有向无环图

`public/js/workflow-core.js` 的 `Workspace.run(documentId?)` **只在显式调用时**从开始节点运行：先用 `parseDocument` 重新校验完整文档（含端口和无环性）并生成不可变快照，再确认所有节点的类型和版本已注册、恰好有一个 `execution: 'entry'` 节点且它至少有一条出边；任一条件不满足就在调用执行器或发请求前报错。即使未知版本位于运行范围外，也会阻止整份流程运行。`parseDocument` 对导入、恢复和编辑提交统一限制**至多一个已识别 entry**，非法文档整体拒绝而不安装部分变更；无入口的旧 v1 文档允许恢复/编辑，但运行会提示添加开始节点，若入口无出边则提示连接处理节点的“启动”输入。不会静默改旧图或补连线；补一个开始节点并接入处理节点即可运行。空工作流也因缺少入口不能运行；每次运行重新计算，不依赖前一次输出缓存或服务器业务状态；没有单节点运行入口。

执行计划先沿开始节点的出边（control 与 data 均可）求可达任务／展示节点，再仅对这些节点的数据输入补入其依赖的 `execution: 'data'` 被动来源；**不会沿被动数据节点的其他出边扩张执行范围**。未触发的节点标为 `skipped`，不请求外部服务；可达节点若依赖范围外的 task／control 来源，也不会偷偷执行范围外任务，而是跳过该依赖分支。先 `await` 入口执行成功，再调度被动数据及其余可达节点；入口失败则其余活动节点跳过，入口取消则停止后续执行。可达下游须等所有已连接的 data/control 上游成功；上游失败或未完成时跳过该下游，独立已触发分支继续。必需输入未连接使本节点失败；上游缺少已声明输出使上游失败、依赖它的下游跳过，不将缺失伪装成空字符串。`inputs` 只包含只读数据端口值，`controls` 单独提供只读控制端口值，内置对比仍从 `inputs.a/b` 向原接口提交 `{left,right}`；控制输入不混入业务参数。输出按声明逐项校验和冻结，缺失或类型错误导致失败。`validateConnection` 拒绝自连、环、端口不存在、`dataType` 或 `kind` 不匹配及一个输入多来源。工作区所有流程共用 `ExecutionPool`，**最多 3 个执行器同时运行**（不是每流程 3 个）；排队任务支持取消。运行停止后，尚未完成的扩展执行器仍占用名额，直到其 Promise 真正成功或拒绝才释放，不能靠反复停止/重跑突破上限；扩展执行器应响应 AbortSignal 并自行结束资源清理。

节点状态为 `queued / running / succeeded / failed / skipped / cancelled`，未运行时流程状态为 `idle`；运行后为 `succeeded / partial / failed`，用户停止后为 `cancelled`。汇总**只统计本次活动范围内的全部 `execution: 'task'` 节点**，包括仅通过控制输入触发的任务；全部成功为 `succeeded`，部分成功为 `partial`，没有成功为 `failed`。入口失败直接为 `failed`，取消为 `cancelled`；范围外的 `skipped` 不计汇总，入口或文本等 `entry/data` 成功也不能掩盖任务失败。`getRuntime(id?)` 提供所属文档的运行快照，节点 `states: Map<nodeId,{status,message,outputs}>`，还包含 `running/runId/startedAt/finishedAt`；执行输出不属于工作流文档。

## 运行锁、切换与停止

- `Workspace` 在核心层拒绝对**正在运行的该流程**执行文本/配置、名称、结构、连线、撤销/重做、复制和删除等业务修改；运行中仍可保存视口、切换到其他流程或创建流程。其他流程可独立编辑/运行，但仍分享并发池。切换菜单或流程不会终止旧流程；事件带 `documentId` 供视图按归属更新。
- `stop(id?)` 将排队/执行中的节点标为 `cancelled`，中止 `AbortSignal` 并阻止继续调度。每轮运行有独立 `runId` 与独立 runtime 对象；回调仅能修改仍属于这次运行、尚未停止的流程状态。即使执行器忽略取消并迟到返回，旧输出也不能回填到新运行或其他流程。
- 取消信号可中止浏览器等待及请求，但**不保证服务端已经开始的计算立即停止**。内置 `createServices()` 只向已有同源 `/api/content-compare/json` 或 `/api/content-compare/env` 发 `POST`，每次发送本次完整 `{left,right}`，30 秒超时、支持取消、`credentials: 'same-origin'`、`cache: 'no-store'`，并校验响应结构；失败不会本地重算。挂载页面、恢复草稿、导入或切换流程都不请求服务。
- 运行结果只保留在本页内存。节点内容/连线等非布局变更以及相关撤销重做使该流程旧结果失效；纯布局编辑、视口调整保留结果。页面刷新或关闭后只恢复文档，**不恢复未完成任务、执行状态或结果，也不自动运行**。

## 工作区、历史与边界

`new Workspace({registry,storage,services,onStorageError})` 可从传入的浏览器 `localStorage` 恢复；存储键 `nestcloud:workflows:v1`。自动保存的白名单只有 `{version:1,activeId,documents}`：文档包括节点配置（含用户输入原文）、连接和视口，不包含运行输出、运行状态、撤销历史、执行器函数或应用认证信息。最多 30 份工作流，每份历史最多 30 条、所有历史快照总预算 8 MiB；历史只在内存中。连续配置输入在 600 ms 合并一次撤销，视口操作不入历史。`insertSubgraph({nodes,edges},id?)` 校验后一次性重建标识并插入子图；`updateLayout([{id,position?,size?}],id?)` 一次提交多节点布局。两者均遵守运行锁、预算和原子性，分别只占一步撤销；用于模板载入和多选拖动，不是子流程执行功能。`create/select/rename/duplicate/remove/importDocument/exportDocument` 管理多份流程；整份复制可保留唯一入口，复制所选入口或向已有入口的图插入包含入口的子图会整体拒绝。导入新建副本，不覆盖原标识，格式无效或已注册入口重复则拒绝。未知节点/版本的配置在受限 JSON 规则内保留，但无法执行整图。

| 预算 | 上限与处理 |
| --- | --- |
| 单文档/导入文本 | 每份最多 **4 MiB**（UTF-8 字节），原始 JSON 字符串和规范化文档分别校验；最多 100 节点、300 连线 |
| 工作区文档 | 最多 **8 MiB** 累计序列化文档；超限变更不提交；浏览器实际配额仍可能更小 |
| 单文本、配置与视图 | 每侧文本最多 500000 UTF-16 字符；配置深度不超过 16；坐标绝对值不超过 100000，节点尺寸 160–2400，缩放 0.2–2 |
| 历史 | 每图至多 **30** 步，工作区所有历史快照合计 **8 MiB**，最早项可被裁剪；仅内存 |
| 并发 | 整个工作区共享最多 **3** 个运行中的执行器 |
| 结果 | 工作区累计输出值最多 **32 MiB**，完成流程结果最多保留 **10 份**；超限优先清理其他较早的非运行中结果，仍超限则该节点失败；结果仅内存 |

这些是核心预算，不代表 `localStorage` 保证有足够实际空间。写入失败时保留页面内存中的当前内容，使用 `onStorageError` 提示用户及时导出；不能把“内存已更新”当作“本地已保存”。恢复时若草稿损坏、不可读取、超限或文档格式版本不兼容，进入**保护模式**：显示临时空工作流而不静默覆盖原键；必须由用户显式新建或成功导入后，才允许替换受保护的草稿。旧 v1 无入口草稿仍可恢复和编辑；导入受格式、结构、连线、唯一入口及预算校验，未知节点实现版本在受限规则内保留但运行前阻止整图执行，错误导入不得污染已有文档/历史。

**隐私**：文本节点中的 JSON/ENV 原文、任意配置及导出 JSON 可能包含密钥；`localStorage` 和导出文件以**明文**保存，既不加密也不自动脱敏。避免在共享设备输入秘密，导出分享前人工审查内容。运行才会向本服务发送两侧完整文本；现有对比接口不持久化、不缓存、不外发原文及结果，见 [内容对比边界](../content-compare/实现与边界.md)。HTTP `no-store` 不影响浏览器本地草稿的保存。

## 资源位置与构建

唯一可部署静态资源源目录是 `apps/system-service/public/`；工作流核心、节点模块和页面片段在该目录，X6 浏览器包由 `apps/system-service/scripts/workflow-graph.entry.mjs` 经 esbuild 输出到 `public/vendor/workflow-graph.js`，不依赖 CDN，也不新建页面托管服务。可在仓库根目录执行：

```bash
pnpm --dir apps/system-service run build:workflow
```

`apps/system-service/package.json` 的 `build` 与 `prestart`、`prestart:dev`、`prestart:debug`、`prestart:prod` 均串联 `build:workflow`；`prestart*` 还继续执行既有 `build:common`。构建脚本用 `typeof document !== 'undefined'` 包裹浏览器 X6 产物，避免后端 Node 静态扫描加载它时访问 DOM。该保护只针对生成的 vendor 文件，不代表运行时可在无 DOM 环境挂载画布。页面按 vendor、core、nodes、palette、view 的顺序加载，再由管理台挂载。`workflow-palette.js` 为无 DOM 的目录/搜索纯逻辑，支持 Node 行为测试；搜索和折叠状态不写入工作流草稿。`nest-cli.json` 按部署资源文件后缀匹配并排除原子写入的 `.tmp.*` 文件，避免临时文件消失时静态监听复制失败；新增文件后需要重新构建或重新启动监听使其纳入文件清单，已有文件修改继续热更新。
