# 执行与存储

## 执行入口和有向无环图

页面 `public/js/workflow-core.js` 的 `Workspace.run(documentId?)` **只在显式调用时**从开始节点运行，浏览器将本次完整文档/凭据发送给 `POST /api/workflow/run`；后端每次创建独立的无 DOM Workspace，复用相同的核心、节点注册定义和调度规则。外部客户端也可经[执行 API](./执行API.md)直接提交完整输入：先用 `parseDocument` 重新校验完整文档（含端口和无环性）并生成不可变快照，再确认所有节点的类型和版本已注册、恰好有一个 `execution: 'entry'` 节点且它至少有一条出边；任一条件不满足就在调用执行器或发请求前报错。即使未知版本位于运行范围外，也会阻止整份流程运行。`parseDocument` 对导入、恢复和编辑提交统一限制**至多一个已识别 entry**，非法文档整体拒绝而不安装部分变更；无入口的旧 v1 文档允许恢复/编辑，但运行会提示添加开始节点，若入口无出边则提示连接处理节点的“启动”输入。不会静默改旧图或补连线；补一个开始节点并接入处理节点即可运行。空工作流也因缺少入口不能运行；每次整图运行重新计算，不依赖前一次输出缓存或服务器业务状态。局部重跑见下方“从节点运行与结果失效”。

执行计划先沿开始节点的出边（control 与 data 均可）求可达任务／展示节点，再仅对这些节点的数据输入补入其依赖的 `execution: 'data'` 被动来源；**不会沿被动数据节点的其他出边扩张执行范围**。未触发的节点标为 `skipped`，不请求外部服务；可达节点若依赖范围外的 task／control 来源，也不会偷偷执行范围外任务，而是跳过该依赖分支。先 `await` 入口执行成功，再调度被动数据及其余可达节点；入口失败则其余活动节点跳过，入口取消则停止后续执行。可达下游须等所有已连接的 data/control 上游成功；上游失败或未完成时跳过该下游，独立已触发分支继续。必需输入未连接使本节点失败；上游缺少已声明输出使上游失败、依赖它的下游跳过，不将缺失伪装成空字符串。`inputs` 只包含只读数据端口值，`controls` 单独提供只读控制端口值，内置对比仍从 `inputs.a/b` 在后端直接调用 `ContentCompareService` 计算 `{left,right}`；控制输入不混入业务参数。输出按声明逐项校验和冻结，缺失或类型错误导致失败。`validateConnection` 拒绝自连、环、端口不存在、数据类型不相容（相同类型或基类型与其语义子类型之间才相容）、`kind` 不匹配、同一来源重复接入多来源输入，以及非 `multiple` 输入接入多个来源；多来源输入在分发时汇总为按上游节点画布位置排序的 `[{ name, value }]` 数组。类型不同但相容的连线在分发前按输入端口类型校验实际值，不合格时该节点失败。后端所有任务共用 `ExecutionPool`，**最多 3 个执行器同时运行**（不是每流程 3 个，FIFO 且不保证公平）；排队任务支持取消。执行器通过 `suspend` 等待人工确认时暂时归还名额，结束后重新排队。运行停止后，尚未完成的扩展执行器仍占用名额，直到其 Promise 真正成功或拒绝才释放，不能靠反复停止/重跑突破上限；扩展执行器应响应 AbortSignal 并自行结束资源清理。

节点状态为 `queued / running / succeeded / failed / skipped / cancelled`，未运行时流程状态为 `idle`；运行后为 `succeeded / partial / failed`，用户停止后为 `cancelled`，编辑使部分结果失效后为 `stale`（工具栏显示“结果部分过期”）。区域等 `execution: 'annotation'` 的画布标注不建立运行状态（显示为未运行），只修改它们也不会把结果标为过期。汇总**只统计本次执行范围内的全部 `execution: 'task'` 节点**，包括仅通过控制输入触发的任务；全部成功为 `succeeded`，部分成功为 `partial`，没有成功为 `failed`。入口失败直接为 `failed`，取消为 `cancelled`；范围外的 `skipped` 不计汇总，入口或文本等 `entry/data` 成功也不能掩盖任务失败。`getRuntime(id?)` 提供所属文档的运行快照，节点 `states: Map<nodeId,{status,message,outputs}>`，还包含 `running/runId/startedAt/finishedAt`；执行输出不属于工作流文档。

## 从节点运行与结果失效

- 编辑只让**变化节点及其全部下游**的结果失效：节点类型、版本、名称或配置变化，节点增删，以及连线增删的目标节点都算变化，再沿新旧两版连线向下游扩散。其余节点结果保留，流程状态变为 `stale`；全部失效时回到 `idle`。纯布局、视口和流程改名不影响结果；撤销/重做按同一规则比较前后文档。
- `Workspace.runFrom(nodeId, documentId?)` 重跑指定节点及其开始可达范围内的下游。页面将本页仍有效的范围外成功上游输出显式装入同一次请求的 `previousOutputs`，与 `fromNodeId` 成对提交；后端仅接纳运行范围外必需的 task 上游，不读取上一任务服务端状态，也不接受范围内旧输出。开始节点和被动数据节点本次重新求值；上游 task 缺少成功结果时在调用执行器前拒绝，提示先运行整图。节点未连接开始节点时同样拒绝。范围外其他分支的结果在页面保持不变，汇总状态只统计本次重跑的任务。画布在除开始节点外的已安装节点头部提供“从此节点运行”按钮。
- 典型用途：修正飞书查找配置后从查找节点重跑，复用已生成的 AI 周报，避免再次调用模型；如需新的模型输出，应显式从 AI 节点或整图重跑。

## 运行锁、切换与停止

- `Workspace` 在核心层拒绝对**正在运行的该流程**执行文本/配置、名称、结构、连线、撤销/重做、复制和删除等业务修改；运行中仍可保存视口、切换到其他流程或创建流程。其他流程可独立编辑/运行，但后端所有任务仍分享节点执行池。切换菜单或流程不会终止旧流程；事件带 `documentId` 供视图按归属更新。
- 页面 `stop(id?)` 必须显式调用 `POST /api/workflow/stop`（专用 `X-Workflow-Token` 头）；收到成功才采纳取消，失败时保留订阅与运行锁，不假报已停止。后端将排队/执行中的节点标为 `cancelled`，中止信号并阻止后续调度；已发出写请求后仍可能远端已写入。每轮运行有服务端独立 `runId` 与 runtime；旧输出不能回填到其他流程或下一次运行。关闭 SSE、页面切换或视图销毁不等于 stop。
- 页面只向固定同源 `/api/workflow/*` 请求任务，不为每个节点从浏览器分别请求 `/api/content-compare/*` 或 `/api/workflow-capabilities/*`。后端复用相同的节点定义和核心，JSON/ENV 对比直接调用 `ContentCompareService`，四个远程原子能力在逐次校验 DTO 后直接调用既有 Service，不循环调用自己的 HTTP 接口；原独立接口仍可由其他调用方直接使用，其断开取消/`confirmed:true` 规则**不迁移到任务接口**。AI 原子调用不设主动时限，但活动任务有创建起绝对 2 小时截止；其他能力保持自身预算。飞书实际矩阵的确认挂起时释放节点执行槽，接受后重新争槽并检查停止/期限；停止或连接断开不保证撤销已经发出的写入。挂载页面、恢复草稿、导入或切换流程都不创建新任务。
- 页面断线按任务 revision 接收最新 SSE 快照并用 `status` 补齐节点输出；不以断线标记执行失败，也不重新 POST run。任务后台继续；同页切换流程仍更新各自 runtime，视图销毁仅退订流并撤销本地弹窗，页面内状态轮询可继续收敛。浏览器 token 和运行结果只保留本页内存；刷新或关闭后只恢复文档，**不恢复任务 token、未完成任务、执行状态或结果，也不自动运行**。服务端任务在短期 TTL 内可由已保管 token 的外部调用方查询，但服务重启立即丢失。

## AI 上下文兼容与执行内存

新建 AI 节点为 `ai-text@2`，必须保存 `contextWindowTokens`（4096～1000000 的整数，默认 100000），不接受 maxTokens。旧 `ai-text@1` 文档可缺省该字段并保留废弃的 maxTokens，导入、localStorage 恢复和导出不迁移、不回写；界面仅回退显示注册定义的默认值，无字段输入事件时不进入待保存集合。v1 执行器在内存中按迁移规则补默认并剔除 maxTokens 后再调用服务，每次请求显式携带上下文；用户可点击节点上的“升级到 v2”显式迁移。

服务端长输入分批/归并的材料和任务要求仅在本次调用内存中处理，不持久化。单次 ai-text 最多 3 个上游调用并行；统一任务还共享最多 3 个节点执行槽、9 个真实能力调用在途额度（逐个 AI client 调用计数），不新增并发 UI。估算和 20% 余量不保证真实模型上下文；任一批失败或停止不返回部分结果，后续依赖节点不能消费中间材料，详见 [AI 接口与归并契约](../workflow-capabilities/API.md#ai-文本生成)。

## 后端短时任务与事件

每次运行显式提交完整 `document` JSON 字符串、`runtime` 和可选 `dateContext`；日期节点所在执行范围要求 `dateContext:{now:带时区ISO时间,timeZone:IANA时区}`，页面点击时冻结浏览器时间/本地时区。使用 `Intl` 计算当地日界和夏令时，不依赖服务端时区；整图不复用旧结果，局部重跑还须成对提交 `fromNodeId/previousOutputs`。`POST /run` 返回 `{runId,accessToken,expiresAt}`；后续 `GET /status?runId=…&nodeId?`、`GET /events?runId=…`、`POST /stop`、`POST /confirm` 仅用 `X-Workflow-Token` 头授权。SSE 的 snapshot/node-state/confirmations/run-finished 共享逐任务递增 revision，只带状态/待确认、不带完整输出；断线重新订阅取得最新快照，不重放历史，完整输出查 status。接口详情及可控本地示例见[执行 API](./执行API.md)。

服务器仅在**单进程短时内存**保留任务：最多 3 活动、20 保留；预留与完成结果合计 128 MiB；活动创建起绝对 2 小时，终态结果 15 分钟，确认最多 10 分钟且不超过任务 deadline。每任务至多 3 个独立待确认写入，模态框串行展示。每 run 最多 4 个 SSE 订阅、全局最多 12；15 秒心跳，阻塞写缓冲下一帧仍未 drain 就断开慢订阅，客户端查最新状态恢复。停止后的底层调用若无视取消，真实能力调用名额和预留容量直到 Promise 结清仍占用。状态查询/心跳/确认均不续期；多实例需粘性路由但不共享状态，重启全部丢失。没有任务级用户认证：`/run` 必须由可信网络或网关认证限流保护；token 只授权已创建任务的查询、停止、确认，不保护创建入口。AI baseUrl 可为内网目标，必须限制可信调用方和出口；发布前请阅读[安全与执行边界](../workflow-capabilities/安全与执行边界.md)。

## 工作区、历史与边界

`new Workspace({registry,storage,runner,services,onStorageError})` 的页面实例通过可注入的 runner 使用后端执行，从传入的浏览器 `localStorage` 恢复文档；存储键 `nestcloud:workflows:v1`。自动保存的白名单只有 `{version:1,activeId,documents}`：文档包括节点配置（含用户输入原文）、连接和视口，不包含运行输出、运行状态、撤销历史、执行器函数或应用认证信息。最多 30 份工作流，每份历史最多 30 条、所有历史快照总预算 8 MiB；历史只在内存中。连续配置输入在 600 ms 合并一次撤销，视口操作不入历史。`insertSubgraph({nodes,edges},id?)` 校验后一次性重建标识并插入子图；`updateLayout([{id,position?,size?}],id?)` 一次提交多节点布局。两者均遵守运行锁、预算和原子性，分别只占一步撤销；用于模板载入和多选拖动，不是子流程执行功能。`create/select/rename/duplicate/remove/importDocument/exportDocument` 管理多份流程；整份复制可保留唯一入口，复制所选入口或向已有入口的图插入包含入口的子图会整体拒绝。导入生成新标识，不覆盖原文档；默认名称带“副本”，文件编辑入口使用 `importDocument(raw,{preserveName:true})` 保留原名称，仍清理本地凭据且不恢复运行或历史。格式无效或已注册入口重复则拒绝。未知节点/版本的配置在受限 JSON 规则内保留，但无法执行整图。

| 预算 | 上限与处理 |
| --- | --- |
| 单文档/导入文本 | 每份最多 **4 MiB**（UTF-8 字节），原始 JSON 字符串和规范化文档分别校验；最多 100 节点、300 连线 |
| 工作区文档 | 最多 **8 MiB** 累计序列化文档；超限变更不提交；浏览器实际配额仍可能更小 |
| 单文本、配置与视图 | 每侧文本最多 500000 UTF-16 字符；配置深度不超过 16；坐标绝对值不超过 100000，节点尺寸 160–2400，缩放为有限正数且最大 2（取消 0.2 下限） |
| 历史 | 每图至多 **30** 步，工作区所有历史快照合计 **8 MiB**，最早项可被裁剪；仅内存 |
| 并发 | 后端所有任务共享最多 **3** 个运行中的节点执行器；真实能力调用另外受全局 9 在途、27 排队额度约束（含 AI 每次真实调用） |
| 结果 | 页面工作区与后端独立执行实例均按端口值累计序列化体积限制为 **32 MiB**，同一对象经多个节点输出也逐次计量；页面完成流程结果最多保留 **10 份**，超限先清理其他较早非运行中结果，仍超限则本次接纳失败。后端结果另受任务总容量与 TTL 约束；均不持久化 |

这些是核心预算，不代表 `localStorage` 保证有足够实际空间。写入失败时保留页面内存中的当前内容，使用 `onStorageError` 提示用户及时导出；不能把“内存已更新”当作“本地已保存”。恢复时若草稿损坏、不可读取、超限或文档格式版本不兼容，进入**保护模式**：显示临时空工作流而不静默覆盖原键；必须由用户显式新建或成功导入后，才允许替换受保护的草稿。旧 v1 无入口草稿仍可恢复和编辑；导入受格式、结构、连线、唯一入口及预算校验，未知节点实现版本在受限规则内保留但运行前阻止整图执行，错误导入不得污染已有文档/历史。

**隐私**：文本节点中的 JSON/ENV 原文、任意配置及导出 JSON 可能包含密钥；`localStorage` 和导出文件以**明文**保存，既不加密也不自动脱敏。避免在共享设备输入秘密，导出分享前人工审查内容。点击运行会向同源执行入口发送**完整工作流文档及 runtime 凭据**（可能包含文本中的敏感信息），后端对比节点直接调用既有 `ContentCompareService`，不从浏览器另发对比 HTTP 请求；结果不持久化，见 [内容对比边界](../content-compare/实现与边界.md)。原子节点可显式查询 GitHub、向所配置 AI 发送提示词与上游内容、查询或确认后写入飞书；开始节点可填写本流程专用凭据：它们随草稿明文保存在 `localStorage`，但导出文件不含、导入文件中的值也不采用。凭据引用、预算和外部副作用见 [能力安全说明](../workflow-capabilities/安全与执行边界.md)。HTTP `no-store` 不影响浏览器本地草稿的保存。

## 快捷保存与文件来源

顶部保留名称、新建、导入、导出、运行、停止及用户确认的区域按钮；工作流可见时 `Ctrl+S`／`Command+S` 从名称、节点输入和侧栏搜索等焦点统一触发文件保存并阻止浏览器保存网页。其他路由不拦截该快捷键，按住产生的 repeat 事件及正在输入法组合的事件不重复保存。保存前同步提交节点内容、未失焦名称与视口；错误立即中止，不发送半旧参数。

`public/js/workflow-files.js` 的 `WorkflowFileService` 将文档 ID、原文件名和 SHA-256 关联：

- 项目目录打开时取得 `{filename,text,revision}`，同文件同版本已有草稿直接切换复用，保留未保存编辑；版本变化导入新的原名流程，旧草稿不删。普通外部导入也保留文档原名称，但尚未绑定项目文件。
- 已绑定流程直接按关联 filename 与 expectedRevision 原位保存，成功先更新返回的新版本，再处理下一次排队保存，不反复确认。显示名称改变不隐式重命名文件。版本冲突不自动刷新并覆盖，应从项目目录重新打开最新版本；旧编辑仍保留在本地，可导出。
- 未绑定流程首次按安全的 `名称.json` 保存。仅未知同名文件的首次冲突要求确认，取消不写入；确认重试后再次变化则拒绝，不无限重试。导出仍是浏览器下载，不是项目文件保存。
- `save({id,name,text})` 在调用时固定内容快照，版本在队列执行时读取，避免两次 Ctrl+S 因自身第一次保存而产生假冲突。切换当前流程不改变旧请求目标；销毁后不再启动排队任务，也不把迟到结果回写到新视图。
- 文件来源元信息单独保存在 `nestcloud:workflow-files:v1`，格式 `{version:1,records:[{id,filename,revision}]}`，最多 30 项、64 KiB，不含正文、凭据、运行状态或结果，不进入工作流导出。恢复严格校验文件名和版本、过滤不存在的文档 ID；损坏时保留原键，现有草稿记为来源不明的双 null 标记并拒绝直接保存，需从目录重新打开或导出处理。该标记在后续元信息保存与恢复中保留，新增文档不受影响。
- 元信息写入失败时维持本页内存关联，显示刷新后须重新打开的警告；不能把磁盘已成功保存的文件谎报为失败。保存成功通知包含真实文件名；只在目录当前可见且展开时刷新列表，保留查询和折叠。

取消、超时或断线不保证撤销服务端已经完成的保存，结果不明应先确认文件状态。执行器仍只消费本次完整参数，来源关联不是服务端任务状态。画布仅通过 Ctrl／Command+滚轮缩放，取消20%的业务下限；图形库以非零浮点精度保护避免奇异矩阵，文档校验接受任何有限的正缩放值，最大2。

## 项目目录读写

项目目录固定为 **`apps/system-service/public/workflow/`**，由后端通过受约束接口列出、读取和显式保存工作流 JSON；这是用户确认的唯一文件存储例外，不是通用文件管理或服务端业务状态存储。前端 `ProjectDirectoryService` 使用固定同源 `/api/workflow-directory` 接口，不再调用目录选择器，不需要本机文件权限，刷新页面后仍能打开同一目录。接口见 [项目目录 API](./API.md)。

- 仅列当前层级的普通 JSON 文件，不浏览子目录、不接收目录或绝对路径参数。目录和文件都限制在固定根内，拒绝符号链接、硬链接、路径分隔符、控制字符和 Windows 保留设备名。文件名最多 120 个 UTF-16 字符且 UTF-8 最多 255 字节，不得以点开头或含 `.tmp.`，主干不得全是点或带首尾空白；目录枚举最多 1000 个条目，超限明确报错，不静默截断。
- 单文件和前端读取文本均限制 **4 MiB（UTF-8）**。服务端使用已有工作流 `parseDocument` 和注册元数据重新校验格式、版本、节点及连线预算；规范化白名单字段并重置已知 `localConfig` 节点配置，保证开始节点凭据不进入保存文件或 API 返回文本。未知节点按原协议保留受限配置，不能因读取自动执行。
- 读取 API 返回受控文本及原始文件字节的 SHA-256 版本；同文件同版本的已有草稿直接切换，否则通过 `Workspace.importDocument` 保留名称导入新标识并关联来源。失败不污染已有文档或历史，新导入状态为 idle，不自动运行；切换前先提交当前流程输入和名称，其他运行中的流程不受影响。读取不会改写文件。
- 目录面板仅提供文件名搜索、文件夹展开与文件读取，不含保存表单。搜索只过滤已加载列表，不触发目录请求；NFKC、大小写不敏感和多词全匹配规则与节点库一致。后端保存接口和前端可测试的 HTTP 适配继续保留：调用方须提供完整文档快照和目标文件名，不隐式采用切换后的流程，不保存运行结果、状态、历史或 Token 配置。
- 保存请求必须显式携带 `{filename,text,expectedRevision}`。未关联文件首次 null 仅允许新建，同名时确认后携带冲突版本重试一次；已关联文件直接携带已知版本，不弹重复覆盖确认。文件再次变化或被移除均拒绝覆盖。项目文件只在快捷键显式操作时保存，localStorage 自动草稿保持独立。
- 后端使用短时内存互斥和目录临时锁串行化协作进程，锁内重新检查文件版本；同目录独占创建临时文件，写入关闭后再提交。新建采用不覆盖已存在目标的提交方式，覆盖在确认版本一致后原子替换；失败保留原文件并清理自己的临时文件。文件占用等系统错误返回可重试失败，不以成功状态掩盖。
- 临时锁和临时文件使用 `.tmp.*` 命名，不参与静态构建复制；锁不保存业务内容。进程异常退出可能遗留锁，必须先确认没有服务进程仍在写入，再由运维清理，不自动按时间抢占活锁。操作系统目录权限应仅允许可信服务和维护人员写入；协作锁不能阻止不遵循协议的外部编辑器在最后检查后改写文件。
- 专用 HTTP 边界限制 JSON 正文预算、严格校验请求字段、设置 no-store，在公共日志前擦除正文，禁止跨来源写入；异常响应不包含输入、凭据、磁盘路径或堆栈。所有文件名和错误均以纯文本呈现，不执行文件内容。
- `workflow-directory.js` 将同一份工具 DOM 移入 `#workflow-sidebar-host`，仅跟随工作流根视图的 hidden 属性显示，不复制或重新创建面板；销毁时断开观察器、取消请求并恢复原 DOM 位置，以支持重新挂载。搜索、折叠、侧栏位置和画布尺寸不写入工作流文档或历史。布局样式单独位于 `public/css/workflow-layout.css`，仅当前路由启用，其他页面的滚动和尺寸保持原有行为。
- 目录列表在打开导航或手动重新展开文件夹时刷新；搜索导致的临时展开和折叠恢复不请求接口。刷新失败保留旧列表，异常通过页面原有错误出口显示；文件夹内不显示状态、空态或解释文本。前端请求有 30 秒主动等待上限，销毁视图会取消等待并丢弃迟到结果。保留的保存接口中，取消、超时或断线不保证撤销服务端已完成的保存，结果不明确时应重新查询确认；客户端不保留跨请求默认覆盖版本。

### 静态资源与部署

文件接口和 Nest 静态托管的 `/public/workflow` 都直接使用同一固定源目录；该窄路径优先于原有 `/public` 构建资源映射，保存后无需等待复制、重新构建或重启即可访问新 JSON。其他页面仍使用既有静态资源入口。隐藏临时文件不作为静态资源公开，缺失文件不回退到 `dist/public/workflow` 的旧副本。

目录定位依据服务代码位置，不随启动工作目录改变。部署应保留 `system-service/public/workflow` 并授予运行账号读写权限，升级时不得删除已有文件；只分发 `dist` 时，也必须在其上一级服务根目录提供这个固定目录，不能把 `dist/public/workflow` 当作新的数据源。服务端文档校验所用浏览器脚本可从随构建交付的 `dist/public/js` 加载，源代码测试使用 `public/js`。

**隐私与发布：**目录中的文件是明文公开资源，可通过 `/public/workflow/<文件名>` 访问，不应保存私有工作流或把秘密写入普通文本节点。服务端只清理已知本地配置，无法自动识别所有文本中的秘密；既有手工维护文件应在发布前人工检查。此例外不允许数据库、session 或其他目录保存业务状态。

## 资源位置与构建

唯一可部署静态资源源目录是 `apps/system-service/public/`；工作流核心、节点模块和页面片段在该目录，X6 浏览器包由 `apps/system-service/scripts/workflow-graph.entry.mjs` 经 esbuild 输出到 `public/vendor/workflow-graph.js`，不依赖 CDN，也不新建页面托管服务。可在仓库根目录执行：

```bash
pnpm --dir apps/system-service run build:workflow
```

`apps/system-service/package.json` 的 `build` 与 `prestart`、`prestart:dev`、`prestart:debug`、`prestart:prod` 均串联 `build:workflow`；`prestart*` 还继续执行既有 `build:common`。构建脚本用 `typeof document !== 'undefined'` 包裹浏览器 X6 产物，避免后端 Node 静态扫描加载它时访问 DOM。该保护只针对生成的 vendor 文件，不代表运行时可在无 DOM 环境挂载画布。页面按 vendor、core、data、capabilities、nodes、palette、capability-view、execution、view 的顺序加载，再由管理台挂载。`workflow-palette.js` 为无 DOM 的目录/搜索纯逻辑，支持 Node 行为测试；搜索和折叠状态不写入工作流草稿。`nest-cli.json` 按部署资源文件后缀匹配并排除原子写入的 `.tmp.*` 文件，避免临时文件消失时静态监听复制失败；新增文件后需要重新构建或重新启动监听使其纳入文件清单，已有文件修改继续热更新。
