# 模板生成 JSON 时必须显式序列化引用值

## 问题与触发条件

文本模板的普通字符串引用按原文插入，适合拼接自然语言，但不能直接作为 JSON 结构片段。将 `[{{data.0}}]` 用于提取首行时，如果上游的首项不是数组，而是字符串 `["a"],["b"]`，模板会生成合法的两行矩阵 `[["a"],["b"]]`。后续通用矩阵校验无法区分它与正常数据，可能扩大写入行范围。

原周报样例的五列筛选偶然挡住了这类输入；移除筛选节点时不能依赖提示词约束或写入确认代替类型保护。

## 根因

同一个模板既支持自然语言插入又承担 JSON 组装，字符串原样替换丢失了“字符串值”和“JSON 结构”的边界。先替换再 JSON.parse 不等同于安全序列化。

## 解决方式

- 普通占位符保持既有自然语言行为。
- JSON 组装使用固定 `json:` 前缀，例如 `[{{json:data.0}}]`。每个引用值通过 JSON.stringify 序列化后插入；字符串保留字符串类型并正确转义，不被解释为数组结构。
- `json:` 后继续使用既有受控字段路径，不增加函数调用、表达式或原型链访问。
- 解析后仍执行矩阵类型、预算和范围校验；首项为字符串、对象或空数组时不得进入写入确认，合法首行之外的数据不参与写入。
- 每次写入仍显示实际范围和完整矩阵并要求确认，不把预期列数当作实际范围。

## 回归验证

`workflow-data.spec.ts` 覆盖字符串引号、换行、反斜杠、矩阵片段、数组、null、数值和布尔值的 JSON 序列化，以及非法路径拒绝。测试仅使用可控输入，不请求外部服务。（`public/workflow/*.json` 样例已不再纳入测试；写入行列约束由 `workflow-capabilities.spec.ts` 覆盖。）
