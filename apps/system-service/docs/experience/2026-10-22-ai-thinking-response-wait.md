# AI 思考模式导致完整任务等待或失败的排查

## 问题与触发条件

2026-10-22 对原始周报任务进行真实模型调用诊断：输入约 1829 tokens。使用提供方默认思考行为时，非流式请求出现上游 HTTP 500，或约 60 秒后连接断开；现有证据**不能判定**是哪一层造成了约 60 秒的断开，也不能据此断言本地服务设置了 60 秒主动超时。

另一次流式诊断在约 80 秒时由诊断方主动停止，当时仅收到约 8332 个思考字符、正文为 0。80 秒是本次诊断的主动停止点，**不是**服务或提供方的超时阈值；流式仅用于观察生成阶段，不是本项目正式模型调用模式。

仅在同一类请求中添加 `enable_thinking: false` 后，一次完整请求约 16.45 秒成功，返回合法 JSON，包含 `markdown` 和 `values` 字段，`values` 为 1 行 5 列。本记录只保留上述排查所需的聚合信息，不包含密钥、完整 prompt、真实业务记录、提供方私有域名或 requestId。单次成功不承诺所有提供方或网络环境均有相同耗时。

## 处理与边界

- 本次约定 `runtime.ai.enableThinking?: boolean`：可选、非 nullable、严格布尔，缺省 `false`；Token 配置页“启用 AI 思考”默认不勾选，浏览器旧值缺失或不严格等于 `true` 都按 `false`，工作流与旧周报本次请求显式传递。
- 共用模型客户端的每次上游调用均发送 `enable_thinking: input.enableThinking ?? false`。不支持该参数的提供方可能拒绝请求；不自动删参数重试，避免默默切回不期望的思考行为。
- 保留非流式调用、不为工作流增加主动超时、不设置输出 Token 上限，以及非空文本、`finish_reason === 'stop'`、响应预算等完整性检查。旧周报原有显式超时参数仍按其接口契约处理；不能把本次观察到的约 60 秒断开归因于本地 60 秒主动时限。
- 本次变更后用运行中接口和本机模拟上游确认：省略/false 均发送 `enable_thinking: false`，显式 true 发送 true，字符串与 null 在外呼前被拒绝。但原始请求的一次真实提供方复测仍返回 HTTP 500，说明关闭思考不保证消除提供方所有错误；应分别验证参数是否正确透传，以及上游本身是否可用。
- 短连通性请求成功只证明该请求链路可用，不证明完整任务能按时返回合格正文；`max_tokens` 也不保证约束思考耗时或思考内容。遇到长时间等待，应分别核对本次开关、任务规模、上游错误和连接状态，不用增加输出 Token 限额或自动删参重试代替定位。

相关契约见 [独立 AI 接口](../workflow-capabilities/API.md#ai-文本生成)和[旧周报接口](../frontend/周报.md#接口)。
