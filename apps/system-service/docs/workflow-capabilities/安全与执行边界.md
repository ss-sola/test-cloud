# 安全与执行边界

## 凭据与本次执行

带 `credentialGroup` 的远程节点配置只保存固定的 credentialRef:'token-config'，表单不渲染该字段，也不提供密钥输入字段；节点内以说明和“前往 Token 配置”链接提示凭据来源。执行时按凭据组决定来源：GitHub（Token）、AI（地址、密钥、模型及思考开关）、飞书（App ID、App Secret）三组中，本次运行的开始节点填写了该组任一项时**整组使用开始节点的值**（首尾空白会去除），须填写完整，否则节点失败且不回退、不混拼；该组在开始节点全部留空时，才从当前浏览器既有 nestcloud:release-tokens:v1 读取。凭据随本次同源 POST 完整提交，不作为端口输出、运行结果、远程节点配置或导出文件的一部分。凭据缺失时不请求接口。

开始节点的凭据字段以密码框显示（autocomplete=new-password，避免浏览器填入登录密码），由开始节点定义的 `localConfig` 保证：随工作流草稿保存在 `localStorage`，导出时重置为空值，导入文件中的值被丢弃；流程内“复制流程”保留原值。开始节点配置只允许这些凭据键，不能借此写入接口地址或其他字段。

这不代表 localStorage 已加密：Token 配置本身仍是浏览器明文配置，任意普通文本/JSON 输入也可能包含用户手动粘贴的秘密。受控远程节点拒绝导入多余 credential/API URL 字段，不能保证自动发现任意用户文本里的密钥。

画布的前端执行适配仅访问固定同源 `/api/workflow/run/status/events/stop/confirm`；后端使用相同节点实现直接调用既有 Service，仍按原能力 DTO 校验，不向本机 `/api/workflow-capabilities/*` 回环发 HTTP。五个独立原子能力 HTTP 接口仍保留供直接调用，其断开取消和飞书 `confirmed:true` **不适用于**统一任务协议。文档不加载代码或任意执行入口；模板不执行 JavaScript，字段路径不访问原型链。Markdown 仅以 DOM 安全白名单渲染，不解释 HTML、图片或 javascript 链接。

## 外发目标

- 联网工作日开关只访问固定 raw.githubusercontent.com/NateScarlet/holiday-cn/master/{year}.json，不接收 URL、不转发任何业务凭据；政府通知链接仅为溯源元数据，不发送额外请求。日期节点无 credentialGroup，开启开关也无需 Token。来源为第三方整理，结构校验不证明未漏录通知，详见[联网工作日](./联网工作日.md)。
- GitHub 只访问 api.github.com；仓库参数不接受任意主机或 Git 传输协议。
- 飞书只访问 open.feishu.cn。用户 Wiki/Sheet URL 仅用于提取资源标识，不作为 HTTP 请求目标；要求受支持租户的 HTTPS 地址和明确 sheet。
- AI baseUrl 来自本次浏览器配置，后端用 `new URL` 构造 `/chat/completions` 路径。不预解析 DNS，不检查公网/私网、IP、主机名后缀或端口，不固定解析结果；HTTP/HTTPS 域名、IP、内网地址和自定义端口可作为目标。URL 的账号与 query 由 Axios 原生处理，fragment 不发送；HTTPS 使用 Node 默认 TLS 证书校验，不跟随重定向，也不自动使用环境代理（`proxy: false`）。

请求层不提供 SSRF/IP 过滤或目标可信性判断。配置的服务可能收到 API Key 与业务内容，使用者需要自行确认该地址可信及服务器可访问范围。

AI 提示词可以包含提交正文、模板及其他上游内容。用户运行该节点即将其发往配置的提供方；接口不会替用户判断提供方是否可信，也不会执行 AI 返回的文本。

## 请求、日志与异常

新端点使用受约束 DTO、嵌套校验、严格字段与限额，不以未经验证的 Record 对象接收业务参数。凭据不放在 query 或 URL。

五条路径使用独立敏感 HTTP 边界：有界 JSON parser、no-store、固定协议错误、完成/关闭时清理 request.body，以及不向前端回显 DTO/上游原文的专用异常 filter。后端详细诊断日志仅过滤凭据及明确的回显请求字段，不主动打印业务请求正文；common-service 不做变更。

GitHub 和飞书请求仍使用既有 `ExternalHttpClientService`/`fetch` 路径；不要把它们与模型传输混为一谈。模型请求由工作流和旧周报共用的 `src/client/ai/ai-text-client.service.ts` 处理：每次使用本次 runtime 凭据新建 `OpenAiCompatibleChatModel`（继承 `@langchain/core` 的 `BaseChatModel`），调用 `model.invoke`；模型不使用 `fetch` 或 `ExternalHttpClientService`。适配器显式选择 Axios Node HTTP adapter（`adapter: 'http'`、`timeout: 0`、`maxRedirects: 0`、`maxContentLength`、`proxy: false`），发送非流式 Chat Completions，不自动改走 Responses API，不发送输出 Token 上限参数。`cache: false`、`maxRetries: 0`，不缓存模型或凭据，不自动重试。`timeout: 0` 表示传输层没有主动截止；只有调用方显式传入 `timeoutMs` 才建立应用层截止信号，工作流不传该值，旧周报保留原有显式超时。

模型原始响应以 JSON 校验首项非空文本和 `finish_reason === 'stop'`；其他完成原因（含 `length`）、响应超预算、非成功状态与传输错误会转为不回显上游正文、prompt 或凭据的受控异常，不能将残缺文本传给下游。Axios 的 `maxContentLength` 在解压读取时限制响应字节，另校验收到的 UTF-8 字节数；网络/上游/代理自身仍可能断开。其他 GitHub/飞书调用的既有日志策略不等于模型客户端会记录原始上游错误正文。标准 LangSmith 跟踪以 `traceable({ tracingEnabled: false })` 和 `callbacks: []` 显式关闭，不修改 `process.env`；不承诺阻止外部自行注册的任意全局 callback 插件。当前依赖为 `@langchain/core@1.2.20`、`axios@1.20.0`、`langsmith@0.11.0`，不使用 `@langchain/openai`。

原子能力独立请求与统一任务均不建立数据库、Redis 缓存或持久化队列；任务仅在单进程内存中短时保留，固定 `public/workflow/` 定义文件仍是唯一明确允许的文件例外，不含业务执行状态。旧周报作业保持原样。统一任务启动 `/api/workflow/run` **无用户认证**：Origin 限制、同源路径和任务 token 只限制浏览器来源/已创建任务访问，不限制无 Origin 的服务端调用方创建任务。上线须放在可信网络，网关为不可信调用方实施认证、限流与出口控制，尤其 AI baseUrl 可指向内网；token 持有者可读结果、停止及确认写入，委托 token 即委托这些能力，`accepted:true` 不证明人工审核。任务 token 仅经 `X-Workflow-Token` 头发送，不放 query、URL 或持久化浏览器存储。

## 预算

统一任务另有独立额度：`/run` 总正文 64 MiB、完整文档 4 MiB、局部旧输出最多 100 项/32 MiB/深度 160，stop/confirm 各 4 KiB；最多 3 活动/20 保留任务，活动预留加结果总预算 128 MiB；跨任务共享 3 个节点执行器（FIFO 无公平保证）、9 个真实能力调用在途与 27 个排队调用（AI 每次模型调用分别计数），取消不提前释放未结清的额度/预留。活动任务绝对 2 小时，终态结果 15 分钟；同时最多 3 个待确认项、确认最长 10 分钟且不越过任务截止。SSE 每任务 4、全局 12 订阅，15 秒心跳，慢连接断开以最新快照补齐。详见[执行 API](../workflow/执行API.md)。以下单能力请求预算不代替任务额度：

| 范围 | 上限 |
|---|---|
| JSON 值 | 深度 16，序列化 UTF-8 1 MiB；现有文本长度仍为 500000 UTF-16 字符 |
| HTTP JSON body | 2 MiB |
| 上游单响应 | 2 MiB，读取过程受限，不整读无界响应 |
| 联网工作日 | 日期节点开关，默认关闭；首尾含最多 366 天/3 年数据，串行单次 15 秒/总计 45 秒，每响应 256 KiB，无缓存/重试/猜测降级 |
| GitHub | 每次最多 500 提交，默认 100；日期跨度最多 366 天；超预算明确失败 |
| AI | prompt 最多 200000 字符，systemPrompt 最多 20000；contextWindowTokens 默认 100000，整数 4096～1000000；不设置本地输出 Token 上限，不发送提供方 Token 上限参数 |
| AI 分批执行 | 单次最多 3 批并行，64 个初始批次、每轮最多 64 批、4 轮归并、128 次总调用；单轮中间结果总字符最多 500000；不截断、不返回部分结果 |
| 飞书查找 | 指定范围最多 500 行、50 列、10000 单元格 |
| 飞书写入 | 最多 200 行、50 列、2000 单元格；单格最多 8000 字符，矩阵 UTF-8 最多 512 KiB |
| 飞书坐标 | 最大绝对行 1000000，最大列 ZZ；写入矩阵与明确范围一致 |

AI 新节点（`ai-text@2`）与请求不包含最大输出 Token 配置，配置中出现 maxTokens 会被拒绝；旧 `ai-text@1` 节点或旧 API 请求中的 maxTokens 只作兼容接收并忽略，不能通过旧默认4096继续限制提供方，也不能将其解释成 contextWindowTokens。新前端每次显式传入模型上下文；v1 节点缺键仅在执行器内存中按迁移规则补100000，旧直接请求允许同一无状态技术默认，不依赖历史业务状态或回写草稿。前端能力服务只按最新版本规则校验执行配置，旧版本节点在执行器内先迁移再调用。模型自身的默认/上下文限制不由本服务解除；上游若返回 length 截断，仍拒绝把不完整文本交给下游 JSON/飞书写入。

输入 Token 用 UTF-8 字节数保守估算，从窗口中预留20%作为生成余量并另扣256消息开销，systemPrompt、阶段指令与共享任务要求也占预算。估算可能提前分片，不保证提供方实际计数、真实模型上下文或输出长度。首轮无损分片均返回严格 `{instructions,content}` JSON，任务/格式要求按源次序提取去重，在后续每轮共享的 user 上下文中显式传递，不提升到 system 权限；原 systemPrompt 每轮重复。中间结果按原序分组且不拆单项；单项尾组不外呼，每轮项数严格减少，末轮才生成单一原格式文本。单项过大、要求自身过大、无法收敛或执行预算超限明确422，不截断、不拼接冒充最终结构。

并发 3 是单个 ai-text 分批调用边界；统一任务还对所有任务设置共享节点/真实能力调用额度，**独立原子能力 HTTP 调用不由统一任务额度管理**。后端任务不增加持久化、Redis 缓存或自动重试；分片/归并中间结果只留本次调用内存，不作为可恢复状态或对外端口输出。

输入/输出过大、GitHub 结果超预算、AI 生成被截断等不能悄悄作为完整结果向下游传递。范围预算不等于服务端持久存储配额。

## 停止与写入后果

统一任务的 AI **原子调用自身**不设主动超时，但任务活动期限固定为创建起绝对 2 小时；时间到会停止调度并请求取消。浏览器断开 SSE 只退订，不取消后端任务；同页流程切换后仍可收敛状态，页面刷新不持久保存 token、状态或结果且不自动恢复。必须显式 POST stop 才请求取消；stop 失败不可假报取消。既有四个**独立能力 HTTP 接口**仍保留客户端断开取消语义与各自时限，旧周报的 aiTimeoutMs 不受影响。网络/提供方即便忽略取消，额度与预留直到真实调用 Promise 结清才归还；终态不等于外部计算或写入已回滚。

独立能力 HTTP 请求依旧在客户端断开时尽可能把取消传至远程 I/O；正常 POST 请求体结束不能被当作取消。统一执行任务与 HTTP/SSE 生命周期解耦：只有显式 stop、任务期限或服务关闭才取消，断线和订阅重连不触发后续自动 `/run`。模型客户端将 signal 传给 LangChain `invoke` 和 Axios，但上游忽略取消时实际调用仍记账至结清，迟到结果不得被旧 runId 回填到新任务。AI 分批任一失败取消兄弟调用，不启动排队项或后续轮次，不返回部分结果。

外部副作用不能由本地 AbortSignal 撤销。统一任务的飞书写入根据实际 wikiUrl/range/values 产生一次性确认 ID（不信任导入文档的 `confirmed:true`），页面通过 `/api/workflow/confirm` 分别确认最多 3 个独立待确认项；接受前不会写入，拒绝、10 分钟超时、任务停止/到期均不授权写入。决定在等待前原子消费，重复/过期确认返回 409；接受后须重新取得共享执行槽并复查任务期限/停止。confirm 响应仅表示决定已记录，写入结果以节点 status 为准。独立能力写入端点仍要求直接调用者显式提交 `confirmed:true`。相同数据可跳过，不自动重试写入；发出写请求后若网络失败或取消，远端可能已写入，应核实后再重跑。写入节点 v2 在确认前先校验矩阵行列：超出 maxRows（默认 1）或与非零 expectedColumns 不一致时拒绝，不截断、不弹确认。

统一任务的确认等待最长 10 分钟，且受任务 2 小时绝对截止约束；等待时通过核心 suspend 暂时归还共享节点执行名额，决定后重新排队取得名额。独立 HTTP 写入端点没有这一确认状态机，继续采用本次 `confirmed:true`。

飞书写入对以公式敏感前缀开头的文本在发送前添加单引号前缀进行转义；该实现未进行真实飞书设备/租户验证，不承诺远端一定隐藏此前缀或完整证明求值语义。应先在非生产单元格确认远端显示符合预期，再用于实际数据。

浏览器恢复、导入、样例插入和切换页面都不自动运行；尤其不能由导入的 confirmed:true 获得写入授权。

## 验证方式

外部服务使用可控 transport/resolver/request mock，不进行真实 GitHub/AI 网络测试或飞书写入；不停止开发服务。独立能力传输测试仍可用 Axios HTTP adapter 的受控本地端点，而不是按 `fetch` mock 推断模型行为。统一任务的核心/前端/HTTP/服务端/日期可控测试见[执行与存储](../workflow/执行与存储.md#验证入口)；浏览器脚本以受控 mock 验证节点、表单、状态恢复和确认，不等同于真实外部网络或人工设备验收。
