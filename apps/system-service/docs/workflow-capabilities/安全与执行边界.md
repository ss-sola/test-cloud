# 安全与执行边界

## 凭据与本次执行

远程节点（定义标记 remote）配置只保存固定的 credentialRef:'token-config'，表单不渲染该字段，也不提供密钥输入字段；节点内以说明和“前往 Token 配置”链接提示凭据来源。执行前从当前浏览器既有 nestcloud:release-tokens:v1 读取 GitHub、AI 或飞书凭据，随本次同源 POST 完整提交，不作为端口输出、运行结果、节点配置或导出文件的一部分。凭据缺失时不请求接口。

这不代表 localStorage 已加密：Token 配置本身仍是浏览器明文配置，任意普通文本/JSON 输入也可能包含用户手动粘贴的秘密。受控远程节点拒绝导入多余 credential/API URL 字段，不能保证自动发现任意用户文本里的密钥。

前端适配仅访问四个固定的 /api/workflow-capabilities/* 端点，不从导入文件加载代码或任意接口地址。模板不执行 JavaScript，字段路径不访问原型链。Markdown 仅以 DOM 安全白名单渲染，不解释 HTML、图片或 javascript 链接。

## 外发目标

- GitHub 只访问 api.github.com；仓库参数不接受任意主机或 Git 传输协议。
- 飞书只访问 open.feishu.cn。用户 Wiki/Sheet URL 仅用于提取资源标识，不作为 HTTP 请求目标；要求受支持租户的 HTTPS 地址和明确 sheet。
- AI baseUrl 来自本次浏览器配置，后端用 `new URL` 构造 `/chat/completions` 路径。不预解析 DNS，不检查公网/私网、IP、主机名后缀或端口，不固定解析结果；HTTP/HTTPS 域名、IP、内网地址和自定义端口可作为目标。URL 的账号与 query 由 Axios 原生处理，fragment 不发送；HTTPS 使用 Node 默认 TLS 证书校验，不跟随重定向，也不自动使用环境代理（`proxy: false`）。

请求层不提供 SSRF/IP 过滤或目标可信性判断。配置的服务可能收到 API Key 与业务内容，使用者需要自行确认该地址可信及服务器可访问范围。

AI 提示词可以包含提交正文、模板及其他上游内容。用户运行该节点即将其发往配置的提供方；接口不会替用户判断提供方是否可信，也不会执行 AI 返回的文本。

## 请求、日志与异常

新端点使用受约束 DTO、嵌套校验、严格字段与限额，不以未经验证的 Record 对象接收业务参数。凭据不放在 query 或 URL。

四条路径使用独立敏感 HTTP 边界：有界 JSON parser、no-store、固定协议错误、完成/关闭时清理 request.body，以及不向前端回显 DTO/上游原文的专用异常 filter。后端详细诊断日志仅过滤凭据及明确的回显请求字段，不主动打印业务请求正文；common-service 不做变更。

GitHub 和飞书请求仍使用既有 `ExternalHttpClientService`/`fetch` 路径；不要把它们与模型传输混为一谈。模型请求由工作流和旧周报共用的 `src/client/ai/ai-text-client.service.ts` 处理：每次使用本次 runtime 凭据新建 `OpenAiCompatibleChatModel`（继承 `@langchain/core` 的 `BaseChatModel`），调用 `model.invoke`；模型不使用 `fetch` 或 `ExternalHttpClientService`。适配器显式选择 Axios Node HTTP adapter（`adapter: 'http'`、`timeout: 0`、`maxRedirects: 0`、`maxContentLength`、`proxy: false`），发送非流式 Chat Completions，不自动改走 Responses API，不发送输出 Token 上限参数。`cache: false`、`maxRetries: 0`，不缓存模型或凭据，不自动重试。`timeout: 0` 表示传输层没有主动截止；只有调用方显式传入 `timeoutMs` 才建立应用层截止信号，工作流不传该值，旧周报保留原有显式超时。

模型原始响应以 JSON 校验首项非空文本和 `finish_reason === 'stop'`；其他完成原因（含 `length`）、响应超预算、非成功状态与传输错误会转为不回显上游正文、prompt 或凭据的受控异常，不能将残缺文本传给下游。Axios 的 `maxContentLength` 在解压读取时限制响应字节，另校验收到的 UTF-8 字节数；网络/上游/代理自身仍可能断开。其他 GitHub/飞书调用的既有日志策略不等于模型客户端会记录原始上游错误正文。标准 LangSmith 跟踪以 `traceable({ tracingEnabled: false })` 和 `callbacks: []` 显式关闭，不修改 `process.env`；不承诺阻止外部自行注册的任意全局 callback 插件。当前依赖为 `@langchain/core@1.2.20`、`axios@1.20.0`、`langsmith@0.11.0`，不使用 `@langchain/openai`。

后端不保存业务数据，不创建新队列，不通过 Redis 缓存凭据或结果；旧周报作业保持原样，不被原子节点复用。

## 预算

| 范围 | 上限 |
|---|---|
| JSON 值 | 深度 16，序列化 UTF-8 1 MiB；现有文本长度仍为 500000 UTF-16 字符 |
| HTTP JSON body | 2 MiB |
| 上游单响应 | 2 MiB，读取过程受限，不整读无界响应 |
| GitHub | 每次最多 500 提交，默认 100；日期跨度最多 366 天；超预算明确失败 |
| AI | prompt 最多 200000 字符，systemPrompt 最多 20000；contextWindowTokens 默认 100000，整数 4096～1000000；不设置本地输出 Token 上限，不发送提供方 Token 上限参数 |
| AI 分批执行 | 单次最多 3 批并行，64 个初始批次、每轮最多 64 批、4 轮归并、128 次总调用；单轮中间结果总字符最多 500000；不截断、不返回部分结果 |
| 飞书查找 | 指定范围最多 500 行、50 列、10000 单元格 |
| 飞书写入 | 最多 200 行、50 列、2000 单元格；单格最多 8000 字符，矩阵 UTF-8 最多 512 KiB |
| 飞书坐标 | 最大绝对行 1000000，最大列 ZZ；写入矩阵与明确范围一致 |

AI 新节点（`ai-text@2`）与请求不包含最大输出 Token 配置，配置中出现 maxTokens 会被拒绝；旧 `ai-text@1` 节点或旧 API 请求中的 maxTokens 只作兼容接收并忽略，不能通过旧默认4096继续限制提供方，也不能将其解释成 contextWindowTokens。新前端每次显式传入模型上下文；v1 节点缺键仅在执行器内存中按迁移规则补100000，旧直接请求允许同一无状态技术默认，不依赖历史业务状态或回写草稿。前端能力服务只按最新版本规则校验执行配置，旧版本节点在执行器内先迁移再调用。模型自身的默认/上下文限制不由本服务解除；上游若返回 length 截断，仍拒绝把不完整文本交给下游 JSON/飞书写入。

输入 Token 用 UTF-8 字节数保守估算，从窗口中预留20%作为生成余量并另扣256消息开销，systemPrompt、阶段指令与共享任务要求也占预算。估算可能提前分片，不保证提供方实际计数、真实模型上下文或输出长度。首轮无损分片均返回严格 `{instructions,content}` JSON，任务/格式要求按源次序提取去重，在后续每轮共享的 user 上下文中显式传递，不提升到 system 权限；原 systemPrompt 每轮重复。中间结果按原序分组且不拆单项；单项尾组不外呼，每轮项数严格减少，末轮才生成单一原格式文本。单项过大、要求自身过大、无法收敛或执行预算超限明确422，不截断、不拼接冒充最终结构。

并发3是单个ai-text执行边界，不是跨请求共享配额；不新增全局准入、持久化、Redis缓存、队列、重试或主动时限。分片及归并结果只在本次请求内存中存在，不作为可恢复状态或对外端口输出。

输入/输出过大、GitHub 结果超预算、AI 生成被截断等不能悄悄作为完整结果向下游传递。范围预算不等于服务端持久存储配额。

## 停止与写入后果

AI 工作流节点不设置前后端主动时限，超过旧的等待阈值仍可继续等待响应；可随时手动停止，客户端断开也会取消。旧周报与工作流共享模型客户端，但旧周报仍显式传入本次 `aiTimeoutMs`。其他 GitHub/飞书能力和原对比接口的既有时限不变。无限制指工作流应用不主动按时长中断，不代表网络、上游或代理永远不会断开；响应大小与生成完整性检查仍然存在。

前端取消会停止等待、取消请求并阻断后续节点；旧 runId 的迟到输出不能覆盖新运行。后端监听请求中断和响应提前关闭，尽可能传递取消到正在进行的远程 I/O；正常 POST 请求体结束不能被当作取消。AI 分批任一失败也取消兄弟调用，不启动排队项或后续轮次，不返回部分结果。不等待忽略 signal 的底层调用，迟到结果不产生下一轮；模型客户端把 signal 传给 LangChain `invoke` 和 Axios HTTP 请求，但不能保证上游已开始的计算被撤销。

外部副作用不能由本地 AbortSignal 撤销。飞书写入每次需要即时确认，不保存确认标记；不会自动重试写入。相同数据可以跳过，但写前读取与写入不是原子 CAS，不能保证与其他编辑者同时写入时没有竞态。写请求发出后若网络失败或取消，远端可能已经写入，应人工核实，不可盲目自动重跑。写入节点 v2 在读取凭据和确认前先校验矩阵行列：行数超过 maxRows（默认 1）或列数与非零 expectedColumns 不一致时直接拒绝，不截断、不弹确认。

人工确认的等待时间不计入 120 秒请求总超时：读取凭据阶段照常计时，弹出确认后暂停计时并通过核心 `suspend` 归还工作区执行名额，只跟随手动停止；确认后重新开始完整计时，覆盖写请求和响应读取。确认对话框因此不会因用户核对时间过长而被自动关闭，确认期间其他分支也能继续使用并发名额。

飞书写入对以公式敏感前缀开头的文本在发送前添加单引号前缀进行转义；该实现未进行真实飞书设备/租户验证，不承诺远端一定隐藏此前缀或完整证明求值语义。应先在非生产单元格确认远端显示符合预期，再用于实际数据。

浏览器恢复、导入、样例插入和切换页面都不自动运行；尤其不能由导入的 confirmed:true 获得写入授权。

## 验证方式

外部服务使用可控 transport/resolver/request mock，不进行真实 GitHub/AI 网络测试或飞书写入；模型传输验证应使用 Axios HTTP adapter 的可控本地端点，不按 `fetch` mock 判断模型行为。浏览器验证在实际管理台运行节点、表单、连接、Markdown、确认和取消；新远程路径注入受控响应，后端独立以 HTTP/DTO/transport 行为测试验证安全边界。原有 JSON/ENV 浏览器回归继续访问本机真实对比接口。自动事件验证不等同于实体鼠标设备人工验收。
