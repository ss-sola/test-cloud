# 节点与组合

## 能力优先，而不是业务节点

周报是一份工作流组合样例，不注册“周报生成”节点。抓取、模板、AI 和结果展示分别执行，通过有类型的端口传递结果；修改提示词或替换来源不会影响其他节点实现。原周报页面及其生成/任务接口保持不变。

现有开始、文本、JSON 对比、ENV 对比、差异结果继续可用。原子能力节点共十一类（节点库列出各类型最新版本）：

| 类型 | 单一职责 | 主要数据输入 → 输出 |
|---|---|---|
| date-range | 执行时计算上周、本周或自定义日期范围 | 无 → range:date-range |
| json-input | 从配置文本解析 JSON 数据 | 无 → data:json |
| json-parse | 将上游文本解析为 JSON | text:text → data:json |
| json-pick@3 | 按以 context 开头的字段路径从 JSON 中取值 | context:json → data:json |
| json-merge@2 | 将任意多个上游 JSON 组合为对象或拼接为数组 | items:json（必填，多来源）→ data:json |
| text-template@2 | 以只读数据填充文本模板 | context:json、text:text（均可选）→ text:text |
| github-commits | 查询一个 GitHub 仓库的原始提交 | range:date-range → data:commit-list |
| ai-text@2 | 根据提示词调用配置的模型 | prompt:text → text:text |
| text-result | 查看、复制和下载文本、Markdown 或格式化 JSON | text:text 或 data:json（二选一）→ text:text |
| feishu-find-row | 在指定范围按列条件查找唯一行 | matches:match-list → target:sheet-target |
| feishu-write-cells@2 | 向明确目标写入行列受限的二维数据 | target:sheet-target、values:cell-matrix → result:json |

除 date-range/json-input 两个被动来源外，处理/展示节点均带可选 control/trigger 启动输入。只有被动数据输入的独立处理步骤可以直接连接开始节点；作为处理链下游时数据边也可触发，无需为每步另连控制线。仍沿用唯一入口、只执行开始可达分支及所需被动数据、输出冻结、共享并发与失败隔离规则。

## 语义数据类型

date-range、commit-list、match-list、sheet-target、cell-matrix 是以 json 为基类型的语义子类型。连线规则：

- 子类型与 json 双向可连：日期范围可直接作为模板上下文，JSON 输入或取值结果也可接到查找条件、写入矩阵等子类型输入。
- 不同子类型互不相容：例如提交数组不能接到写入矩阵、日期范围不能接到匹配条件，在连线时即被拒绝。
- json 数据进入子类型输入时，运行时先按输入类型做结构校验；不合格则该节点失败，提示“输入“…”不符合 … 数据类型”，不调用服务、不读凭据。完整业务校验（日期跨度、匹配列范围、矩阵预算等）仍由各能力服务负责。

旧流程中两个不同子类型之间的连线在本版本前只能在运行时失败；升级后此类文档的连线校验会拒绝，需要删除错误连线后再导入或恢复。

## 日期与 JSON

日期范围使用浏览器本地时间，以周一为一周开始；生成时转成明确的 ISO since/until 传给后端。上周为前一个完整周，本周为本周一至本次执行时间。输出还包含 startDate/endDate（YYYY-MM-DD），以及数字形式的 start/end（{year,month,day}），方便模板按表格中的写法拼出周标签，例如 `{{context.start.month}}.{{context.start.day}}-{{context.end.month}}.{{context.end.day}}` 得到 `8.24-8.28`。一次运行中日期节点只求值一次，由各下游共享，不在每个远程步骤重新计算。

自定义周期的开始/结束时间是日期字段：可点输入框内右侧的日历图标，在按工作流暗色风格绘制的月历中选取（周一开头，支持上/下月、“今天”、方向键与 PageUp/PageDown 移动、Enter 选择、Esc 或点击外部关闭，写入 YYYY-MM-DD），也可直接手输 YYYY-MM-DD 或含时区的 ISO 时间；两种方式保存为同一个配置值，执行时统一校验。上周/本周周期不使用这两项。

json-input 与现有文本节点一样允许保存未完成草稿；到执行时才解析。json-parse 做相同解析但输入来自上游。JSON 值限深度、字节数和有限数字，不包含函数、undefined 或循环引用；路径访问只读取自有属性，拒绝 __proto__/constructor/prototype。

所有按路径读取输入 JSON 的节点统一以 `context` 表示该节点自身收到的原始 JSON，输入端口也统一命名为 context。json-pick 的字段路径与模板引用 `{{context.…}}` 写法一致（点分隔、数字下标）：输入 `{"values":[1,2,3]}` 时 `context.values` 得到 `[1,2,3]`，`context.items.0.name`、`context[0]` 同理，只写 `context` 表示整个输入，路径必须以 context 开头；字段不存在时节点失败，不补空值、不回退默认值。取值结果保持原始 JSON 类型，不经过文本序列化，因此不存在字符串被误当作结构片段的问题。

json-merge@2 只有一个可接任意多条连线的“输入”，同一上游输出不能重复接入。“对象”方式以**上游节点名称**为键（去除首尾空格），可让模板通过 `{{context.提交记录}}`、`{{context.周报时间范围.startDate}}` 引用多个来源（文本模板只有一个 context JSON 输入，多个来源必须先经 JSON 合并）；名称为空或重名时节点失败，不覆盖。模板路径不支持空格和英文句点，被引用的节点名称应避开这些字符；修改上游节点名称后需同步修改模板引用。“拼接”方式要求每个输入都是数组，按上游节点在画布上从上到下、从左到右的顺序合并一层（例如合并多个仓库的提交数组）。输出同样受 JSON 字节与深度预算限制。

json-merge@1（固定 a/b/c/d 四个输入，对象键为 a/b/c/d）继续保留以便旧流程运行；点击“升级到 v2”会把 a/b/c/d 上的连线统一改接“输入”，合并方式不变，但对象键随之变为上游节点名称，下游模板中的 `{{context.a}}` 等引用需手动改为节点名称。

文本结果节点可直接接 JSON：文本输入与“JSON 数据”输入二选一（都不接或都接时节点失败），JSON 及其语义子类型（如日期范围、提交数组、写入结果）按两空格缩进格式化后展示，无需再经过模板。展示格式选“JSON”时以原文显示并下载为 `.json`；格式化后超过 500000 字符时失败，不截断，可先用 json-pick 缩小范围。端口输出仍是格式化后的文本。

## 文本模板

模板只替换显式引用的数据，不筛选、去重或重排记录。GitHub 原始提交数组（包括空标题和合并提交）会完整传入模板，并随提示词发送给用户配置的 AI。

模板是文本替换，不是模板脚本语言：

- `{{context}}`：整个输入 JSON 的文本。
- `{{context.0.subject}}`：数组第一项的 subject。
- `{{context.b.startDate}}`：经 JSON 合并后 b 输入（如日期范围）的起始日期。
- `{{text}}`：上游文本原文。
- `{{json:context.0}}`：将引用值显式按 JSON 序列化；字符串会加引号并转义，可安全用于组装 JSON。`json:` 后仍只允许 context/text 的安全字段路径，不执行表达式。

新版模板（v2）只接受 context 与 text 两个根，引用 data 会在运行时报错。

普通引用的对象/数组转成 JSON 字符串，字符串原样插入；需要生成 JSON 时使用 `json:` 引用。缺失字段报错，不悄悄补空值。禁止函数调用、表达式和原型链访问；输出超过文本预算时失败，不静默截断。只需从 JSON 中取出某个字段继续作为 JSON 使用时，用 json-pick，不要“模板 → JSON 解析”往返。

## 已移除节点与旧流程

`data-filter` 数据筛选节点已移除，节点库不再提供，也不能新建。已保存或导入的旧流程仍保留该节点配置及连线，作为未知节点展示并允许导出，但运行前拒绝整图执行，不会发出远程请求。不会自动删除、旁路或静默重连。旧周报样例可重新导入下方新版文件；自建流程需手动删除旧节点并核对上下游数据后重连。

## 节点版本与显式升级

ai-text、feishu-write-cells 与 json-pick 的配置结构或语义有变化，按核心的 `type@version` 机制注册新版本，旧版本实现继续保留：

| 节点 | 旧版本 v1 | 新版本 v2 | 迁移规则 |
|---|---|---|---|
| ai-text | contextWindowTokens 可缺省（执行时补 100000）；废弃 maxTokens 原样保存但执行时忽略 | contextWindowTokens 必填，出现 maxTokens 即拒绝 | 缺省上下文补 100000，丢弃 maxTokens |
| feishu-write-cells | 只有起始列，矩阵行列不受节点限制 | 增加 maxRows（1～200，默认 1）与 expectedColumns（0 不限，1～50 时要求精确列数） | maxRows=200、expectedColumns=0，保持旧行为 |
| json-pick | v1 路径相对输入本身（如 `values`）；v2 以 `data` 开头 | v3 以 `context` 开头（如 `context.values`），输入端口为 context | 路径根改为 `context`，data 输入连线改接 context，取值结果不变 |
| text-template | 有 data 与 context 两个 JSON 输入，模板可引用两者 | 只有一个 context JSON 输入，引用改为 `{{context…}}` | data 引用改为 context，data 连线改接 context；同时引用两者时拒绝自动升级，需先加 JSON 合并再手动改写 |

新建节点使用 v2。旧文档中的 v1 节点按原规则继续导入、恢复、导出和运行，不自动改写；节点头下方显示“旧版本 v1”提示与“升级到 v2”按钮，点击后按迁移规则生成新配置并作为一次可撤销编辑保存。升级后的写入节点仍保持原有不限行列语义，需要时再手动收紧 maxRows/expectedColumns。

## AI 模型上下文

AI 节点数字字段“模型上下文（Token）” `contextWindowTokens`：默认 100000，仅允许 4096～1000000 的整数；它是输入分批的技术预算，不是输出 Token 上限。新节点和独立周报 JSON 样例显式保存该值，每次 AI 请求都携带本次窗口。并发由服务端固定治理，不新增并发配置界面，也不改工作区执行器并发。

v1 节点缺少该字段仍可导入、从 localStorage 恢复和导出；界面显示默认 100000，但打开、同步、放弃未保存修改或执行都不会自动回写旧草稿。只有用户实际编辑该字段并校验成功后才保存；执行时由 v1 执行器在内存迁移出新版配置。旧 `maxTokens` 原样兼容保存和导出，但执行时忽略，不能作为上下文窗口，也不发送到接口。前端能力服务只接受新版配置。

长输入按 UTF-8 字节保守估算，预留 20% 输入余量并扣除 256 消息开销，服务端自动分片整理和按原顺序分组归并，最终仍返回一个原格式文本。估算与预留不保证真实模型上下文或输出长度，模型自身的上下文限制仍适用。所有片段提取到的任务/格式要求会显式共享给后续轮次，原 systemPrompt 每轮重复；中间 JSON 不是最终端口输出。完整预算、失败和取消约束见 [接口说明](./API.md#ai-文本生成) 与 [安全边界](./安全与执行边界.md)。

## 周报样例

空画布的“载入周报组合样例”一次插入七个节点、七条连接，可一步撤销，不运行、不上传，也不发布飞书。GitHub 节点命名为“提交记录”、日期节点命名为“周报时间范围”，二者都接入 JSON 合并的同一“输入”，模板以 `{{context.提交记录}}`、`{{context.周报时间范围.startDate}}` 按节点名称引用（改名需同步改模板）：

```text
开始 ─────→ 提交记录 ──────→ JSON 合并 → 文本模板 → AI 文本生成 → 文本/Markdown 结果
                  ↑               ↑
              周报时间范围 ───────┘
```

独立文件 [周报生成.json](../../public/workflow/周报生成.json) 是**生成与飞书推送完整版**，与界面只生成周报的七节点样例不同。源码位置为 `apps/system-service/public/workflow/周报生成.json`，构建后静态路径为 `/public/workflow/周报生成.json`。文件包含 17 个节点（其中两个为区域标注：蓝色“周报md”圈住开始到 Markdown 结果的生成链路，绿色“飞书推送”圈住查找条件、取值、查找与写入）、18 条连线，加入结构化输出解析、Markdown 提取、JSON 取值、飞书查找和逐次确认写入，不含密钥：

```text
… AI 文本生成 → JSON 解析 ─┬→ 文本模板 {{context.markdown}} → Markdown 结果
                          └→ JSON 取值 context.values─────────────┐
日期范围 → 文本模板（周范围、姓名）→ JSON 解析 → 飞书查找目标行 ↓
            └────────── target ──────────────────→ 飞书写入（maxRows 1、expectedColumns 5）
```

完整版配置步骤：

1. 填写 GitHub 仓库/人员，在开始节点或 Token 配置中填写 GitHub、AI 和飞书 App ID/Secret（开始节点填写的组优先，导入后需重新填写）。
2. 在“飞书查找目标行”节点填写带 sheet 参数的 Wiki/Sheets 链接；查找范围默认 A1:B200，可按实际表格修改。
3. “按日期范围生成周范围和姓名条件”文本模板以日期范围为上下文生成查找条件：A 列周范围由模板 `{{context.start.month}}.{{context.start.day}}-{{context.end.month}}.{{context.end.day}}` 按所选日期自动生成（自定义 8.24～8.28 时为 `8.24-8.28`），不再手填；若表格写法不同（如补零、用 ~ 连接），直接修改模板。B 列姓名在模板中替换为实际姓名。注意“上周/本周”的结束日是周日，表格只写到周五时请用自定义日期，或把模板改为只匹配开始日期（如 `{{context.start.month}}.{{context.start.day}}-`）。
4. AI 被模板要求返回 `{markdown,values}` JSON；values 预期是周一至周五一行五列。“提取工作日单行数据”JSON 取值节点按路径 `context.values` 取出 values 交给写入节点，写入节点配置 maxRows=1、expectedColumns=5：多于一行或列数不是五列时在确认前拒绝，**不截断、不只取首行**，因此不会覆盖其他人员。写入默认从 C 列开始，目标行 9 对应 C9:G9。
5. 运行后先查看 Markdown；实际写入前必须对当次目标、实际范围和全部单元格内容单独确认。查找失败、AI JSON 不合法、矩阵行列不符合或拒绝确认时不写入；查找/写入分支失败不影响已成功生成的 Markdown 展示。修正查找配置后可点击查找节点的“从此节点运行”，复用已生成的周报和取值结果，只重跑查找与写入，不再调用 GitHub 和 AI。

完整版 AI 节点的系统提示词只定义通用输出规则：具体格式与结构由任务提示词决定；任务要求 JSON 时，要求标准语法、正确的字符串转义、逐层闭合数组与对象，并在输出前内部核对字段、类型、层级和数组长度。系统提示词不写死周报字段、工作日列数或特定错误片段，这些业务约定仅保留在文本模板和写入节点的行列约束中。提示词不能保证模型始终输出合法 JSON，解析失败仍停止下游写入，不自动替换或修补模型结果。文件更新不会覆盖浏览器 localStorage 中已保存的工作流，已有流程需手动更新，或备份原流程后重新导入新版文件。

界面七节点生成样例的使用步骤：

1. 在开始节点或 Token 配置填写 GitHub Token 和完整的 AI baseUrl/apiKey/model；只想让本流程使用不同凭据时填在开始节点。
2. 在抓取节点填写仓库（owner/name 或标准 GitHub HTTPS 地址）、分支和人员。
3. 选择时间范围；按需要调整提示词。周报格式与中文要求属于模板配置，不是 AI 节点内置规则。
4. 点击整图“运行”。先独立查询 GitHub，再将完整原始数据填充到模板，再独立请求 AI，最后展示 Markdown。

AI 会收到提示词及其中包含的提交记录；这是显式外发，不是本地离线摘要。AI 失败时不会暗中切换成旧周报规则生成器。生成节点结果与状态仅在页面内存，刷新只恢复配置和输入。

## 独立的本地文本流程

```text
开始 ─────→ 文本模板 → 文本/Markdown 结果
                 ↑
              文本输入
```

模板填写 `摘要：{{text}}`，开始连接模板的 trigger，文本连接模板的 text。该流程不要求 GitHub、AI 或凭据，证明模板和展示不依赖周报业务。

## 飞书查找与写入

查找节点显式配置 wikiUrl 与范围，例如 A1:B200；matches 来自 JSON 输入，可为：

```json
[
  {"column":"A","value":"2026-10-12","mode":"contains"},
  {"column":"B","value":"测试人员","mode":"equals"}
]
```

所有条件都要匹配，value 必须是字符串；数字单元格按文本匹配时也提供字符串。唯一性只在指定范围内判断，不扩大到整张表。零行或多行匹配均拒绝，不静默选第一行。

合并单元格按区域取值：例如周范围 A1:A3 合并、B 列为三个人名时，查找“A 包含 8.24-8.28 且 B 等于某人”可以命中该区域内任意一行，与表格界面所见一致。查找范围必须包含合并区域的首行和首列，否则明确报错而不是当作空单元格。

查找输出含 wikiUrl、1 基绝对 row 和 sheetId。写入节点接收 target，再接入二维 values，例如 `[["事项一","事项二"]]`。startColumn 可设 D，若目标 row=9，则明确计算 D9:E9；不固定周报列、姓名或工作日。也可由 JSON 输入直接提供已知坐标，写入不依赖查找节点的服务端状态。新建写入节点默认 maxRows=1，适合“查找到一行、写入一行”；需要写多行时显式调大，expectedColumns 填 0 表示不限列数。

每次写入前出现本次确认，展示目标、实际范围和完整有界数据。确认不是节点配置，不随保存/导出/导入恢复；拒绝或停止不发送写请求。确认等待期间不计入请求超时、也不占用工作区执行名额。写入一旦发出，取消/超时不代表回滚，需先核实远端结果再重跑。界面七节点样例默认不连接飞书步骤；独立 JSON 完整版已连接，但仍逐次确认，导入和恢复不会自动推送。
