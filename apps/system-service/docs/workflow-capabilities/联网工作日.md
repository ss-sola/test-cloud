# 日期范围节点的联网工作日

## 开关与兼容

不增加独立日历节点类型。现有 `date-range@2` 增加“联网获取中国大陆工作日”复选开关（`includeWorkdays`），默认关闭。

- 关闭：只按本次 `dateContext` 计算原有日期范围，不读取日历、不访问凭据。
- 开启：先计算同一日期范围，再联网获取节假日和调休安排；成功后在原 `range` 输出增加 `workdayCalendar`。失败时整个日期节点失败，不输出缺少日历的部分范围。
- `date-range@1` 保持原有配置与纯本地行为。已有节点需点击“升级到 v2”，升级只补 `includeWorkdays:false`，端口和连线不变，可撤销，不自动改写 localStorage。
- 日期节点仍是无输入的被动来源，只有执行范围内依赖它的分支才会求值；载入、导入、打开页面或编辑开关都不会自行请求日历。
- 节点无需 Token，不配置 `credentialRef`，日历能力请求不读取或发送 GitHub、AI、飞书凭据。

原有 `since`、`until`、`startDate`、`endDate`、`start`、`end` 保持原语义。首先按浏览器本次显式 `dateContext.timeZone` 计算范围，日历使用同一民用 `startDate/endDate`；不会把原始 ISO 瞬间改写成上海时区。联网日历本身采用中国大陆（`CN`）和 `Asia/Shanghai` 口径，不代表其他国家、地区或企业自定义考勤。

## 输出与连线

原来的 `range:date-range` 端口不变，仍可接 JSON 合并、模板或 GitHub 查询。开启后附加结构如下（示例为国庆调休上班的周六）：

```json
{
  "workdayCalendar": {
    "region": "CN",
    "timeZone": "Asia/Shanghai",
    "startDate": "2026-10-10",
    "endDate": "2026-10-10",
    "workdays": ["2026-10-10"],
    "days": [
      {"date":"2026-10-10","isWorkday":true,"reason":"makeup-workday","name":"国庆节"}
    ],
    "sources": [
      {
        "year": 2026,
        "url": "https://raw.githubusercontent.com/NateScarlet/holiday-cn/master/2026.json",
        "papers": ["https://www.gov.cn/zhengce/zhengceku/202511/content_7047091.htm"]
      }
    ]
  }
}
```

`days` 按日期升序连续覆盖区间内每一天；`workdays` 只包含其中 `isWorkday:true` 的日期，顺序一致。`reason` 为 `weekday`、`weekend`、`holiday` 或 `makeup-workday`；普通日期 `name` 为空，放假和补班日有受约束名称。前后端检查日期、范围、连续性、工作日列表一致性及来源，输出按白名单重建。

直接接模板时，用 `{{context.workdayCalendar.workdays}}`；经过以节点名称为键的 JSON 合并后，用 `{{context.周报时间范围.workdayCalendar.workdays}}`（日期节点名称需要与引用一致）。不再通过星期几或 Git 提交日期推测工作日。

固定目录 `public/workflow/周报生成.json` 的原“周报时间范围”节点已升级并开启开关，节点和连线数量不增加。提示词从该节点输出读取工作日列表，再均衡分配所有项目的真实事项，仍隐藏项目来源标记、保持单行写入并逐次确认；工作日不固定为五天。已有浏览器草稿不会被文件更新覆盖，需要重新打开新版文件或显式升级后开启。

界面“载入周报组合样例”仍是七节点七连线，默认关闭联网，不增加新的节点类型；按需要开启日期节点上的开关。

## 来源、算法与信任边界

固定使用 [NateScarlet/holiday-cn](https://github.com/NateScarlet/holiday-cn) 的年度 JSON。它是依据国务院放假通知整理的第三方公开数据，**不是政府官方 API，也不是政府原文的独立校验结果**。

1. 在每次运行内，按年份升序串行读取范围涉及的年度文件。
2. 结束日期在 12 月时，还读取下一年度，处理下一年元旦对 12 月的调休。跨年范围中已经包含的年度不重复读取，最多三个文件。
3. 取得年度覆盖项后，先按星期判定普通日期，再应用 `isOffDay:true` 的放假、`false` 的补班覆盖。后年度通知中的同日记录覆盖先年度；单个年度内部同日期重复直接失败。
4. `papers` 必须是非空受约束的 `https://www.gov.cn` 链接，无账号密码、显式端口和 fragment；仅作为溯源信息返回，不额外抓取。年度、记录数量、真实日期、相邻年度偏移、名称和布尔标记均被校验。

这些检查只能保证可检测的结构与内部一致性。**合法 JSON 中漏录一条节假日覆盖项仍可能被当作普通星期日期，不能仅凭 schema、非空数组或政府链接证明第三方数据语义完整。** 输出准确性依赖数据源维护，企业自定义上班安排不在本能力覆盖范围。

## 预算、失败与刷新

- 日期首尾包含，允许单日，最多 366 天；必要年度读取范围为 2007～2100，最多 3 个文件。
- 单年度 15 秒，总计 45 秒，且受统一任务剩余期限或直接 HTTP 断开信号约束；单响应最多 256 KiB。
- 每年度最多 400 个覆盖项、20 个来源链接；名称最多 64 字符，政府来源 URL 最多 512 字符。
- 年度尚未发布或 404 返回 503；网络错误、非成功状态或损坏数据明确失败；超时 504、取消 499，参数错误 400/422。
- 12 月即使不跨年，也可能因下一年度尚未发布而失败。这是保守的完整读取策略，不能为了成功率跳过潜在调休影响。
- 不自动重试，不返回部分年度，不回退“周一至周五”或 AI 记忆；日期节点失败会阻断依赖它的 GitHub、AI 和飞书分支。
- 不增加 Redis、文件或进程级日历缓存，每次重新运行流程都会重新获取。普通工作流任务结果仍按既有内存生命周期处理，不是日历持久化。

独立能力协议见 [API](./API.md#联网工作日日历)，统一任务仍通过原执行 API 直接调用能力 Service，不回环独立端点。
