# 论文查重功能

## 1. 功能边界

论文查重用于比较两段中文、英文或数字文本，发现连续文字重合、少量字符编辑后的近似重合，并在原文位置高亮。

本功能不做以下事情：

- 不连接论文库、互联网或外部搜索服务；
- 不使用 Embedding、LLM、向量数据库或语义模型；
- 不判断学术不端；
- 不把主题相似、同义改写或翻译改写直接当成文字重复；
- 不在服务端保存原文、规范化文本、结果或历史任务。

当前输入上限为每侧 10000 个 JavaScript 字符。算法计算过程只存在于当前请求，页面草稿只保存在用户浏览器本地。

页面入口：

```text
/public/index.html#plagiarism
```

## 2. HTTP 接口

### `POST /api/plagiarism/compare`

请求示例：

```json
{
  "source": "答案 A",
  "target": "答案 B",
  "threshold": 0.6,
  "editDistance": 2
}
```

请求字段：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `source` | string | 必填，最多 10000 个字符 |
| `target` | string | 必填，最多 10000 个字符 |
| `threshold` | number | 可选，`0～1`，默认 `0.6` |
| `editDistance` | integer | 可选，非负整数，不设上限，默认 `2` |

`editDistance` 控制两个连续重复锚点之间允许的插入、删除或替换字符数。设置为 `0` 时只允许完全连续匹配，设置更大值可以合并少量编辑后的重复区域。

错误输入由 DTO 和 `ParamsErrorException` 校验，接口使用 `ResponseUtil.success` 返回成功结果。

## 3. 返回结构

返回结果同时包含顶层兼容字段和两个方向的结果：

```json
{
  "similarity": 0.71,
  "overallSimilarity": 0.71,
  "duplicateRate": 0.31,
  "duplicateLength": 215,
  "sourceLength": 690,
  "targetLength": 580,
  "threshold": 0.6,
  "editDistance": 2,
  "matches": [],
  "sourceToTarget": {},
  "targetToSource": {},
  "steps": []
}
```

### 3.1 方向性结果

`sourceToTarget` 以答案 A 为分母，`targetToSource` 以答案 B 为分母。两者均包含：

- `similarity`
- `duplicateRate`
- `duplicateLength`
- `sourceLength`
- `targetLength`
- `threshold`
- `editDistance`
- `matches`
- `steps`

方向性相似度公式：

```text
similarity = Jaccard × 0.5
           + SimHash × 0.2
           + duplicateRate × 0.3
```

顶层 `overallSimilarity` 是两个方向相似度的平均值：

```text
overallSimilarity = (sourceToTarget.similarity + targetToSource.similarity) / 2
```

顶层 `similarity` 与 `overallSimilarity` 保持一致。方向性 `duplicateRate` 不强行对称，因为 A、B 的分母长度可能不同。

### 3.2 Match 结构

```json
{
  "sourceStart": 10,
  "sourceEnd": 30,
  "targetStart": 18,
  "targetEnd": 38,
  "text": "人工智能技术正在快速改变现代教育",
  "length": 20,
  "sourceContext": "前后文和重复片段",
  "targetContext": "前后文和重复片段",
  "sourceDensity": 0.42,
  "targetDensity": 0.51,
  "density": 0.42,
  "lengthScore": 0.85,
  "densityScore": 0.8,
  "score": 0.835,
  "counted": true,
  "similarity": 0.835
}
```

位置字段统一使用原始输入的 UTF-16 半开区间 `[start, end)`：

```text
[start, end)
length = end - start
```

`text` 是答案 A 原文片段。上下文只用于评分和解释，不会直接计入 `duplicateLength`。

## 4. 当前算法流程

```text
原始文本 A / B
      │
      ▼
文本标准化 + 原文坐标映射
      │
      ▼
按标点、分号、逗号、换行分句/分块
      │
      ▼
块级 3-gram 候选召回
      │
      ▼
LCS 连续匹配锚点
      │
      ▼
编辑距离近似锚点合并
      │
      ▼
连续字符扩展
      │
      ▼
最小长度过滤
      │
      ▼
非重叠候选选择
      │
      ▼
跨块相邻合并
      │
      ▼
上下文窗口和双侧密度计算
      │
      ▼
长度评分 + 密度评分
      │
      ▼
计入/过滤低质量 Match
      │
      ▼
duplicateLength / duplicateRate
      │
      ▼
A → B、B → A、整体综合结果
```

## 5. 文本标准化

`text-normalizer.ts` 对每个 Unicode 字符执行：

- Unicode NFKC 归一化；
- 英文大小写归一化；
- 删除空白和标点对匹配的影响；
- 识别并移除合法 HTML 标签；
- 保留每个规范化字符到原文 UTF-16 区间的映射。

规范化文本只用于计算。前端高亮时使用映射回原文的区间，所以原文中的标点、空格和换行不会被替换掉。

## 6. 分句与分块

`text-segmenter.ts` 按以下边界切分：

- 中英文句号；
- 问号、感叹号；
- 分号、冒号；
- 中英文逗号；
- 换行。

当前保留每个边界形成的独立块，不跨标点强行拼接短句。这样可以避免把：

```text
学生的学习情况，并提高教学效率
```

错误拼接为一个跨标点重复片段。

## 7. 候选和连续匹配

每个 A 块与 B 块先生成去重字符 3-gram：

```text
commonNGramCount === 0
```

的块对不会继续进入 LCS。

有共同 N-gram 的块对执行 LCS。当前最小匹配锚点为 6 个规范化字符，锚点会：

1. 向前扩展完全相同字符；
2. 向后扩展完全相同字符；
3. 合并同一块中间隔不超过 `editDistance` 的锚点；
4. 丢弃扩展后仍不足最小长度的结果。

跨分块合并使用固定最大间隔 8，并要求两侧已有片段至少达到 8 个字符，避免把多个短公共词拼成一段高重复内容。

## 8. 上下文和重复密度

每个重复区间默认取两侧各 20 个规范化字符作为上下文：

```text
contextBefore = 20
contextAfter  = 20
```

上下文不改变 `sourceStart`、`sourceEnd`、`targetStart`、`targetEnd`，只用于计算：

```text
sourceDensity = match.length / sourceContextLength
targetDensity = match.length / targetContextLength
density = min(sourceDensity, targetDensity)
```

双侧取小值，防止一侧上下文很短而把局部片段评分过高。

## 9. 评分和重复率

长度评分：

```text
< 6       = 0
6～9      = 0.3
10～15    = 0.6
16～29    = 0.85
>= 30     = 1
```

密度评分：

```text
< 0.15       = 0
0.15～0.24   = 0.3
0.25～0.39   = 0.6
0.4～0.59    = 0.8
>= 0.6       = 1
```

当前权重：

```text
score = lengthScore × 0.7 + densityScore × 0.3
```

降低密度权重是为了避免长文本上下文把真实连续重复压得过低。只有：

```text
score >= 0.5
```

的 Match 才会计入最终重复区间。

`duplicateLength` 不直接累加 Match，因为 Match 可能重叠。系统会先合并 A 侧区间，再计算：

```text
duplicateRate = duplicateLength / sourceLength
```

## 10. 前端行为

页面入口：

```text
/public/index.html#plagiarism
```

页面提供：

- 答案 A / B 输入框；
- 高亮相似阈值；
- 非负整数编辑距离；
- 实时字符数；
- A → B、B → A 重复率；
- 九步算法数据；
- 多颜色重复片段高亮；
- 鼠标悬浮和键盘聚焦详情；
- 匹配片段联动滚动，两侧可以定位到同一个 Match。

高亮采用 ENV 对比式叠层：

- 底层高亮层显示颜色和片段；
- 上层 readonly textarea 保留原文；
- 两层同步滚动；
- 悬浮/聚焦片段时，A/B 两侧对应片段滚动到可视区域。

输入缓存：

```text
localStorage key: nestcloud:plagiarism:v1
```

缓存内容包括：

- `source`
- `target`
- `threshold`
- `editDistance`

缓存只存在浏览器，服务端不读取之前请求，也不保存这些数据。

## 12. 已知边界

- 语义改写、翻译改写和同义表达不会自动视为文字重复；
- 编辑距离越大，越容易把不相邻证据合并，生产环境应谨慎调节；
- `duplicateRate` 是方向性指标，不等同于整体相似度；
- 该结果是文本重合辅助信息，不是正式学术判定。
