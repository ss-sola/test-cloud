# 外部适配器

## GitHub

`GitHubReleaseClientService` 继承 `RemoteClientBase`，并通过独立 secure transport 封装 Contents、commits、branches、refs、compare、merge 和 create-tag。repository、host、ref、文件路径均校验；compare 只作为差异/可见性依据，不伪造无冲突保证。dry-run 不进入 merge/tag transport；apply merge 接受 201（新 merge commit）或 204（already applied），tag 只接受 201。

分支计划读取 `dev`、`master` 和 API 返回的 `custom/*`，按字节序稳定排序；每个目标独立记录 before SHA，未来 apply 应重新读取并处理竞态。禁止本地 Git 和代码下载。

## Jenkins

`JenkinsClientService` 严格执行：

1. POST 配置的 trigger path；只接受 HTTP 201，body 必须为空，禁止 POST 重试；
2. 从同 origin `Location` 提取本次响应的数字 queue id；
3. 轮询 `/queue/item/{queueId}/api/json`，只从 `executable.number` 得到 build number，处理 cancelled/stuck/blocked/why 和 deadline；
4. 轮询本次 build JSON 至 SUCCESS 或明确失败，不使用 lastBuild；
5. SUCCESS 后请求配置的完整 Pipeline text endpoint，响应按文本读取；
6. 末行（忽略尾部空白）必须为 `Finished: SUCCESS`，从后往前取第一个 `backend-wzj-nodejs-v2:` 后的合法 `1.9.0` tag。

queue/build 编号不硬编码，凭据不进 URL、query、日志或 Redis。当前 `docs/project/jenkins调用文档.md` 的完整 Pipeline path 为空，所以没有该配置时直接 blocked，不发起 POST。
