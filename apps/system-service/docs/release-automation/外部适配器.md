# 外部适配器

## GitHub

`GitHubReleaseClientService` 通过安全 transport 封装 Contents、commits、branches、refs、compare、merge 和 create-tag。repository、host、ref、文件路径和提交消息均校验；compare 只作为差异/可见性依据，不伪造无冲突保证。真实执行时 tag 以固定来源分支 `dev/master` 的当前 SHA 为快照，先做同 SHA 幂等检查，再按独立 gate 创建；并发 422 只通过一次 GET reconcile。页面填写的分支不经过业务格式过滤，原样作为合并目标，合并来源仍固定为 `dev/master`；每次写前后校验目标/source SHA，禁止本地 Git。

分支计划读取 `dev/master` 和 API 返回的 `custom/*`，按字节序稳定排序；执行 Job 针对页面选定的目标分支冻结 before SHA，使用 `dev/master` 作为单一来源分支执行远程合并。apply 每次写前重新校验 expected SHA，201/204 后再次读取目标 SHA；只有 `mode=dry-run` 时不发送 merge/tag POST。禁止本地 Git 和代码下载。

## Jenkins

`JenkinsClientService` 直接使用受控 `fetch` 调用文档中的 trigger、queue、build 和 Pipeline text endpoint，不继承 `RemoteClientBase`。Jenkins package 不区分 dry-run/apply，选中 Jenkins 任务就执行配置的打包接口；GitHub tag/merge 的 mode 规则不影响 Jenkins package。Jenkins 不校验 Git candidate SHA、target branch 或 planHash，只做 URL/path、凭据、HTTP 状态、队列/构建编号和 Pipeline tag 解析。

`JenkinsClientService` 严格执行：

1. POST 配置的 trigger path；只接受 HTTP 201，body 必须为空，禁止 POST 重试；
2. 从同 origin `Location` 提取本次响应的数字 queue id；
3. 轮询 `/queue/item/{queueId}/api/json`，只从 `executable.number` 得到 build number，处理 cancelled/stuck/blocked/why 和 deadline；
4. 轮询本次 build JSON 至 SUCCESS 或明确失败，不使用 lastBuild；
5. SUCCESS 后请求配置的完整 Pipeline text endpoint，响应按文本读取；
从后往前取请求配置的 tag marker 后的合法 release tag。
Jenkins 任务地址支持完整的动态 job URL，例如 `https://jenkins.example.com/job/{folder}/job/{project}/`。服务端只解析同 origin 的 `/job/{folder}/job/{project}/` 路径，动态 folder/project 保持 URL 编码，并自动生成 trigger、queue、build 和 `{buildNumber}/consoleText` 地址；不硬编码 folder 或项目名称。
