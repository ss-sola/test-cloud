# 配置与安全边界

## 配置读取

业务默认配置由 `readReleaseAutomationConfig()` 通过 `getConfig` 和 `ReleaseAutomationConfigKeys` 读取；发布页面提交的 Git/Jenkins/Feishu 配置会覆盖对应默认值；dry-run/apply 由 Job 的 mode 决定，不再使用服务级开关。`ReleaseAutomationVersion` 是服务端默认 tag（默认 `1.9.0`）；发布请求中的 `gitTag` 由页面输入并经过 semver-like tag 校验，作为本次 release unit/version。页面 token 保存在浏览器 localStorage，并随创建 Job 提交，不再强制要求 token 使用 `getConfig` 或 Secret Provider。页面提供完整 Jenkins 任务地址时，服务端自动推导 trigger、queue、build 和 consoleText 路径；没有任务地址或完整 Pipeline 路径时 package 返回 `blocked`，不会 POST。

常用键如下：

| 键 | 默认/要求 |
| --- | --- |
| `ReleaseAutomationVersion` | `1.9.0`，其它值拒绝 |
| `ReleaseAutomationGitHubBaseUrl` | `https://api.github.com` |
| `ReleaseAutomationGitHubAllowedHosts` | `api.github.com` |
| `ReleaseAutomationGitHubTokenRef` | 可选服务端 token 引用；请求级 token 可覆盖 |
| `ReleaseAutomationEnvironmentBeforeRef` / `AfterRef` / `EnvironmentFilePath` | ENV diff 所需；不接受请求覆盖 |
| `ReleaseAutomationModifyLogPath` | `modify-log.sql`，basename 固定 |
| `ReleaseAutomationModifyLogArchiveDir` | `var/release-automation/archive` |
| `ReleaseAutomationJenkinsBaseUrl` | 可选；只允许配置的同 origin |
| `ReleaseAutomationJenkinsTriggerPath` | Jenkins `buildWithParameters` 相对路径 |
| `ReleaseAutomationJenkinsQueuePathTemplate` | 必须含 `{queueId}` |
| `ReleaseAutomationJenkinsBuildPathTemplate` | 必须含 `{buildNumber}` |
| `ReleaseAutomationJenkinsPipelineTextPathTemplate` | 必填；当前 Jenkins 文档为空时保持 blocked |
| `ReleaseAutomationJenkinsCredentialRef` | 可选服务端引用；页面配置 Jenkins token 优先使用 |
| `ReleaseAutomationRedisUrl` | 必填；缺失时拒绝创建或查询 Job，不回退进程内存 |
| `ReleaseAutomationRedisKeyPrefix` | 默认 `release-automation`，与 weekly-report 的 `bull` 隔离 |

timeout、重试、轮询、响应大小和日志上限均有配置键，代码不接受请求体任意透传。

## 页面凭据配置

发布页面提供 Git 地址、分支、项目名称、Jenkins 地址、GitHub/Jenkins token，以及 Feishu App ID/App Secret 字段。字段值保存到 `localStorage`，重新打开页面时恢复；token/secret 使用 password input，但 localStorage 暴露风险由使用者自行承担。代码不会把凭据写入进度消息、错误详情、Markdown 或普通日志；Job 数据会保留本次执行所需的页面配置。


## Secret reference

服务端 token 仍可通过 `secret://` 引用和 `ReleaseSecretProvider` 提供；当页面提交了对应 token 时，页面配置优先级更高。无页面 token 时才使用服务端引用。无 token 或解析失败时 Jenkins fail-closed。

## 网络安全

GitHub 仅允许 HTTPS 和配置的 host，拒绝重定向，并校验 repository owner/name 格式；使用超时、响应大小限制和有限 429/5xx 重试。Jenkins URL 仅允许配置 base URL 的同 origin，路径模板拒绝 `..`、绝对外站和未替换占位符；内网文档中的 HTTP base URL 仍只能访问同 origin。
