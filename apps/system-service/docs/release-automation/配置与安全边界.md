# 配置与安全边界

## 配置读取

发布自动化不从配置文件、配置中心或进程环境读取业务变量。`readReleaseAutomationConfig(runtime)` 只接收 Controller 已通过 class-validator 校验的请求运行配置，并用代码常量补齐固定安全上限。GitHub、Jenkins、ENV diff、modify-log 和 AI 参数沿 HTTP DTO → Job → Worker → adapter 传递。

`targetBranch` 是 GitHub PR base 分支，`branch` 是 Jenkins 构建分支；GitHub PR head 固定为 `dev/master`。两者都是不强制业务前缀的字符串协议值，由对应外部系统判定是否存在。页面以两个独立输入提交，旧 localStorage 草稿只有一个 `branch` 时，会兼容迁移为 `targetBranch`，不会丢失原值。

## 页面凭据与公开进度

发布页面提供 Git 地址、Jenkins 构建分支、GitHub PR 目标分支、GitHub/Jenkins token 和 Feishu 凭据字段。草稿字段写入浏览器 localStorage；token/secret/API Key 的 localStorage 暴露风险由使用者自行承担。服务端状态、进度、错误和日志统一脱敏；token 不进入 `progress.pullRequest`、PR body、页面状态、Job status 或公开日志。

## 网络安全

GitHub 只允许 HTTPS 和请求级 allowlist，拒绝重定向，保留同源约束、URL 编码、超时、响应大小限制和有限 429/5xx 重试。创建 PR 和 tag 等写操作需要 apply gate；dry-run 不发送这些 POST。Jenkins 请求级 URL 仅允许安全的 HTTP(S) 同源任务地址，路径模板拒绝 `..`、绝对外站和未替换占位符。

## 本地与持久化边界

本流程不执行 `git clone`、`pull`、`fetch`、`checkout`、本地 merge、第三方项目本地构建或本地 SQL 执行。后端不以文件或数据库保存业务发布状态；Job 的短期队列数据只用于执行和状态 TTL，公开状态不包含运行凭据。modify-log 从 GitHub Contents 读取，不依赖本地同名文件。
