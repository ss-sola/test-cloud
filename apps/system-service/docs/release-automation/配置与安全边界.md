# 配置与安全边界

## 配置读取

发布自动化不从配置文件、配置中心或进程环境读取业务变量。`readReleaseAutomationConfig(runtime)` 只接收 Controller 已通过 class-validator 校验的请求运行配置，并用代码常量补齐固定安全上限。GitHub、Jenkins、ENV diff 和 modify-log 参数沿 HTTP DTO → Job → Worker → adapter 传递；页面凭据随创建 Job 提交。

唯一的队列基础设施配置是既有 `SessionRedisUrl`，发布队列使用固定的 `release-automation` prefix，与周报队列隔离。HTTP `Port` 与 `SessionRedisUrl` 是 system-service 启动配置，不属于发布业务运行参数。

请求可携带的运行字段包括 GitHub token/base URL/allowlist/超时重试、ENV before/after ref 与文件路径、modify-log 路径与上限、Jenkins 任务地址/分支/tag marker/超时重试、Token 配置中的 nested AI runtime 及 Feishu 页面凭据。`gitTag`、`targetBranch` 与 `branch` 不限制业务前缀或名称格式，仅保留 DTO 的字符串、非空与最大长度边界；repository、ref、文件路径和 SHA 作为 opaque 值传给适配器，由外部系统判定业务有效性。发布 docs 自动按当前 tag 与 GitHub Tags API 返回的上一 tag 收集提交，并固定读取 ENV/modify-log 事实，不按 person 筛选。未提交的可选字段使用模块代码常量，不读取旧 `ReleaseAutomation*` 键。

## 页面凭据配置

发布页面提供 Git 地址、Git 分支、Jenkins 地址、GitHub/Jenkins token，以及 Feishu App ID/App Secret 字段；Token 配置页面同一 localStorage 对象中的 `ai.baseUrl`、`ai.apiKey`、`ai.model` 会在发布提交时作为 `runtime.ai` 传递。Git 分支输入不限制业务前缀或名称格式，页面将同一个值作为 GitHub merge 目标和 Jenkins 构建分支提交。字段值保存到 `localStorage`，重新打开页面时恢复；token/secret/API Key 使用 password input，但 localStorage 暴露风险由使用者自行承担。状态接口、进度、错误和日志会投影/脱敏，不返回凭据；异步 Job 只在短期内部执行数据中保留请求上下文，并在终态清理运行时凭据。

## Secret reference

当前发布页面直接提交本次请求凭据和可选 `runtime.ai`；不再从服务端 `secret://` 配置引用回退。缺少外部服务凭据时，由请求 DTO 或执行阶段阻断；AI 请求失败时 release docs 使用本地事实摘要，不把 provider 错误或 API Key 写入日志。

## 网络安全

GitHub 仍只允许 HTTPS 和请求级 allowlist，拒绝重定向，并保留请求 URL 的同源约束、编码和响应结构解析；repository、ref、文件路径和 SHA 不再执行本地业务格式/形状校验。请求继续使用超时、响应大小限制和有限 429/5xx 重试。Jenkins 请求级 URL 仅允许安全的 HTTP(S) 任务地址，路径模板拒绝 `..`、绝对外站和未替换占位符；内网文档中的 HTTP base URL 仍只能访问同 origin。

## 持久化边界

请求运行配置用于 Job 执行和幂等计算。状态接口的 `ReleaseJobStatusView` 不包含 `pageConfig` 或 `runtime`，错误、进度和日志统一脱敏；BullMQ 执行期间短暂保存执行上下文，终态 updateData 会移除 GitHub/Jenkins/Feishu/AI 凭据，Job 仍受 60 分钟 TTL 和生产 Redis 账号/prefix/访问控制约束。浏览器 localStorage 的凭据风险不由服务端消除。
