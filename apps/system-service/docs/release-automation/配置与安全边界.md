# 配置与安全边界

## 配置读取

发布自动化不从配置文件、配置中心或进程环境读取业务变量。`readReleaseAutomationConfig(runtime)` 只接收 Controller 已通过 class-validator 校验的请求运行配置，并用代码常量补齐固定安全上限。GitHub、Jenkins、ENV diff、modify-log 和 AI 参数沿 HTTP DTO → Job → Worker → adapter 传递。

`branch` 是当前/source 分支，tag、update-log 和 GitHub PR head 使用该值；`targetBranch` 是 PR base，也是 Jenkins 构建分支。两者都是不强制业务前缀的字符串协议值，由对应外部系统判定是否存在。草稿保留独立的 `branch` 与 `targetBranch`；旧 branch-only 草稿将原值保留为 current branch，target 留空并要求用户补填。

## 页面凭据与公开进度

发布页面提供 Git 地址、当前分支、GitHub PR 目标分支、GitHub/Jenkins token 和 Feishu 凭据字段。Jenkins 构建分支由 `targetBranch` 决定。草稿配置写入浏览器 localStorage；token/secret/API Key 的 localStorage 暴露风险由使用者自行承担。服务端状态、进度、错误和日志统一脱敏；token 不进入 `progress.pullRequest`、PR body、页面状态、Job status 或公开日志。

发布页面默认关闭 env → `sys_config` SQL。开启后，新增或变更项连同真实值（包括敏感变量）写入 GitHub `update-log`，应只用于访问受控的仓库；页面在选项旁提示该风险。生成的 SQL 不进入 AI 提示或执行日志，且启用时 Job 状态不返回带 SQL 的 Markdown。

## 网络安全

GitHub 只允许 HTTPS 和请求级 allowlist，拒绝重定向，保留同源约束、URL 编码、超时、响应大小限制和有限 429/5xx 重试。创建 tag、提交 PR、首次写入 Contents 及 Git Data blob/tree/commit/ref 写操作都需要独立 apply gate；写请求不自动重试，dry-run 不发送写请求。update-log replacement 只作用于 current branch：最新可确认的自动 update-log commit 必须是 branch HEAD，且只修改目标文件；检测到人工/非 tip 提交时 fail closed。ref 使用 force update 以替换该 commit，targetBranch 仍只通过 PR 接收改动。最终 HEAD 检查不能消除检查与 PATCH 间的并发 push 竞态；branch protection 拒绝时不绕过。Jenkins 请求级 URL 仅允许安全的 HTTP(S) 同源任务地址，路径模板拒绝 `..`、绝对外站和未替换占位符。

## 本地与持久化边界

本流程不执行 `git clone`、`pull`、`fetch`、`checkout`、本地 merge、第三方项目本地构建或本地 SQL 执行。后端不以文件或数据库保存业务发布状态；Job 的短期队列数据只用于执行和状态 TTL，公开状态不包含运行凭据。modify-log 从 GitHub Contents 读取，不依赖本地同名文件。
