# 初始化与约束

## 当前行为

`EnableTypeOrm()` 会基于配置构造 TypeORM 连接选项，当前默认按 PostgreSQL 运行，依赖的关键配置包括：

- 数据库驱动（当前统一使用 `postgres`）
- 主机
- 端口（默认 `5432`）
- 用户名
- 密码
- 数据库名
- `DbSynchronize`

## 实体扫描路径

当前实体扫描路径指向：

- `${process.cwd()}/dist/**/*.entity.js`

## 审计字段

继承 `BaseEntity` 的实体统一包含 `create_user`、`update_user`、`created_at`、`updated_at` 与 `deleted_at` 字段。

通过 `BaseService.create()` / `BaseService.update()` 写入时，基础服务会从 `ContextService.getCurrentAccount<T>()` 读取当前账号 id，并填充 `createUser` / `updateUser`；无请求上下文或未登录账号时跳过填充，避免启动初始化任务受影响。

若业务服务直接调用 `repository.save()`，需要在保存前复用基础服务的审计辅助方法，且当返回值需要包含数据库生成字段时，保存后应重新查询完整实体再返回。

## 使用约束

- 数据库配置必须通过 `getConfig` 与 `ConfigKey` 提供
- `synchronize` 行为变化时，应同步更新运维与部署文档
- 结构初始化脚本统一维护在仓库根 `sql/*.sql`，当前活动服务脚本使用 PostgreSQL 方言
- 若实体扫描规则、驱动或初始化方式变化，需要同步更新这里与根级 `docs/project/部署与可观测性.md`
