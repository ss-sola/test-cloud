# common-service 初始测试策略

## 当前目标

- 先覆盖共享 `util` 层中稳定、跨服务复用的公开方法
- 先保护分页转换、响应封装、类型归一化这类高收益规则
- 不在首轮测试里引入数据库、注册中心或 Nest 容器依赖

## 当前落点

- `apps/common-service/test/util/value.util.spec.ts`
- `apps/common-service/test/util/response.util.spec.ts`
- `apps/common-service/test/util/page.util.spec.ts`
- `apps/common-service/test/logger/logger.config.spec.ts`
- `apps/common-service/test/config-center/load-config.spec.ts`
- `apps/common-service/test/config-center/validate-config.spec.ts`
- `apps/common-service/test/config-center/config-injector.spec.ts`
- `apps/common-service/test/register/register.spec.ts`

## 分层顺序

- 第一层：`util` 单元测试，优先覆盖静态方法、默认值和异常回落
- 第二层：共享能力行为测试，优先覆盖配置合并、日志配置、别名解析、自动注册边界和公共注入规则
- 第三层：少量集成测试，只在收益明确时验证共享能力协作链路

## 编写约束

- 使用 Vitest（`vi` / `expect`）
- 测试文件统一放在与 `src` 同级的 `test/` 目录，不放进 `src` 树
- 断言以返回结构和公开行为为主，不依赖私有方法
- 依赖项优先使用 `vi.fn()`、`vi.spyOn()` 或内存假对象，不连接真实外部系统
- 修复可稳定复现的问题时，优先补对应回归测试

## 后续扩展建议

- 下一步优先补注册中心 client、远程配置同步与 `AfterAppBootstrapRunner` 的可控行为测试
- 再评估是否需要补少量带 Nest 容器的共享层集成测试
